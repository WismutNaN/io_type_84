# Модуль: аппаратная конфигурация

**Реализация 2026-09-14:** `io-core/src/keyboard.rs` (DTO), `io-platform/src/changes.rs` (модельная валидация/codec), `src/features/editor/Inspector.vue`, `DksEditor.vue`, `MacroEditor.vue`. SET/GET/restore base/Fn/RT/DKS/макроса проверены; физическое исполнение пока нет. До 40 advanced, один advanced на физическую клавишу в одном слое, пары RS/SOCD целиком. [Покрытие](../docs/EDITOR_IMPLEMENTATION.md). Ниже — целевой дизайн; исходная фраза «запись не проверена» относится к исследованию до реализации.

**Ответственность:** допустимое состояние назначений, хода и аппаратных поведений. **Расположение:** `crates/io-core/src/configuration/`.

## Контекст

Это уровень A: параметры штатной firmware, включая аппаратные макросы. Запись
настроек не является перепрошивкой и не требует фонового runtime. Текущий writer
макросов ограничен 512 байтами с каталогом 400 байт; полная ёмкость устройства не
установлена. Расширять её сначала исследованием stock-хранилища. Запись/readback
проверены отдельно от исполнения и сохранения после питания. [Матрица](../docs/INTEGRATION.md).

Проверено чтение обычной и Fn-таблицы по 128 × 4 байта, RT 128 × 8, DKS 64 × 16 и каталога макросов 100 × 4. Запись base/Fn/RT/DKS/короткого макроса проверена GET-сверкой и восстановлением; физическое исполнение остаётся открытым. Сайт для White показывает RS, SOCD, DKS, MT и TGL; это кандидаты для повторения, не готовая гарантия исполнения.

## Публичный интерфейс

| Символ | Тип | Назначение |
|---|---|---|
| KeyboardConfiguration | aggregate | Связное аппаратное состояние и ревизия |
| FirmwareLayer | enum/newtype | Основной/Fn; дополнительные только из capabilities |
| Binding | enum | HID-действие, аппаратный макрос, advanced behavior, Unknown(raw) |
| Actuation / RapidTrigger | value object | Ход, повторное срабатывание/отпускание и флаги |
| FirmwareMacro / DksEntry | entity | Идентификатор в памяти, последовательность/этапы |
| validate_configuration | функция | Ошибки с путями полей и необходимыми capabilities |
| plan_device_change | функция | Доменный diff без I/O |

## Зависимости

DeviceLayout и CapabilitySet из device; целые единицы расстояния/времени. Application управляет чтением и записью через порты. Lighting хранится отдельной моделью, хотя может применяться вместе.

## Инварианты

- Неизвестные записи и резервные байты сохраняются при редактировании соседних настроек.
- Все ссылки на макросы и DKS валидны; удаление используемой записи требует исправления ссылок в черновике.
- Максимальные размеры и диапазоны зависят от устройства, а не от рекламных данных другого SDK.
- Для текущего rtPrecision=0 делитель RT/хода 100; шаг UI 0,01 мм. В домене целые микрометры и проверяемая конверсия.
- Назначение системного Fn и ограничения Fn+F1…F12 проверяются отдельно. Не блокировать их навечно только из-за ограничения UI сайта.
- Нельзя обещать бесконечные аппаратные слои или численность макросов по размеру каталога.

## Намеренно не обрабатывает

Скрипты ОС, контекст активного приложения, runtime double tap, HID-пакеты, восстановление после частичной записи.

## Заметки для реализации

Сначала точный decode/encode с Unknown(raw), затем операции изменения. Проверки: round-trip реальных пакетов; сохранение неотображаемых 44 позиций при изменении одной из 84; отклонение неподдержанного шага; ссылки на удалённый макрос. Спецификация — [PROTOCOL](../docs/PROTOCOL.md), применение — [application](application.md).
