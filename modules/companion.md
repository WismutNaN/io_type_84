# Фоновый помощник ОС

Актуально: 2026-09-14. **Статус: проект доработки существующего runtime.** В текущем
EXE нет tray/автозапуска и гарантированной работы без окна. Цель — полезные действия
на штатной firmware, независимо от расширения полосы. [Уровень B](../docs/INTEGRATION.md),
[ADR-0007](../docs/adr/0007-integration-levels.md), [фаза 10](../docs/PLAN.md#phase-10).

## Что переиспользовать

| Файл | Что уже делает | Что мешает фону |
|---|---|---|
| `crates/io-core/src/automation.rs` | ActionDefinition, варианты ОС, GestureEngine глубины/удержания группы | Нет общего цифрового источника/программных слоёв и всех автоматов жестов |
| `crates/io-platform/src/service.rs` | Один HID worker, FB → rules → actions; configure_automation | UI polling обновляет heartbeat; через 5 с без него worker.stop() выключает наблюдение и правила |
| `crates/io-platform/src/action_runtime.rs` | Отдельная очередь исполнения, отмена по поколению, Windows ввод/текст/три приложения | Нет произвольного ProcessAction и общей модели результата долгой операции |
| `src-tauri/src/lib.rs` | IPC; disconnect при RunEvent::Exit | Нет tray, single instance и независимого управления жизнью окна/runtime |
| [Каталог](action-catalog.md) | Общий черновик, undo/redo, профиль v2, действия/жесты | Данные сейчас в localStorage; фону нужен доступ к применённому профилю без Vue |

Не создавать второй HID reader или новый engine вместо работающего кода.
Сначала отделить владение runtime от окна; затем расширить источники и исполнители.

## Публичная граница следующей реализации

Имена ниже — проект, не существующие IPC-команды.

| Операция / модель | Ответственность |
|---|---|
| CompanionStatus | stopped / starting / running / paused / awaitingDevice / error / stopping, активная версия правил, причина недоступности |
| start / pause / resume / stop | Явное управление помощником; не записывает аппаратный профиль |
| apply_automation | Атомарно заменить программную версию после валидации, отменить старые таймеры/очередь |
| RuntimePreferences | Разрешённая фоновая работа, автозапуск при входе, локальная привязка устройства и активного профиля |
| ProfileRepository | Доступ Rust к применённой конфигурации помощника без localStorage/Vue |
| InputSource | Нормализованные цифровые события или FB с происхождением, временем, поколением и качеством данных |
| ProcessAction | Исполняемый файл/приложение, отдельный список аргументов, необязательный рабочий каталог |
| AutostartPort / SessionLifecyclePort | Настройка запуска и события блокировки/сна/выхода для конкретной ОС |

RuleEngine выдаёт ActionIntent в существующую очередь исполнителя. HID worker не
ждёт завершения запущенной программы, задержек макроса, сетевого запроса или скрипта.

## Владение и остановка

Один Tauri-процесс на пользовательский сеанс. Rust-runtime живёт независимо от
видимости WebView. Повторный запуск показывает существующее окно, не создаёт второго
исполнителя или HID owner. Отдельный постоянно установленный системный сервис не
нужен: интерактивные действия относятся к сеансу пользователя, а службы Windows
изолированы от его рабочего стола.
[Microsoft: Interactive Services](https://learn.microsoft.com/en-us/windows/win32/services/interactive-services).

| Событие | Целевое поведение |
|---|---|
| Первый запуск | Только конфигуратор; помощник и автозапуск выключены |
| Включение помощника | Проверить применённый профиль и необходимые источники; показать running или конкретную причину |
| Закрытие окна при разрешённом фоне | Скрыть редактор; показать доступный tray; runtime продолжает работу |
| Закрытие окна без фона | Завершить приложение с остановкой временных действий/мониторинга |
| Пауза / отключение помощника | Отменить очередь и таймеры, освободить только собственный синтетический ввод; параметры клавиатуры сохраняются |
| «Выход» в tray | Остановить помощник и необходимые источники, закрыть HID, завершить процесс |
| Сон / блокировка / отключение IO | Отменить связанные удержания и отложенные действия; пометить зависимые правила неготовыми |
| Возврат / переподключение | Сверить identity/capabilities, новое поколение; не воспроизводить накопленные события; нужен новый цикл отпускания/взведения |
| Второе устройство / неоднозначная identity | Не назначать автоматически чужую клавиатуру владельцем правил |

UI-наблюдение, rules runtime и диагностическая сессия — разные владельцы подписки
на данные. Закрытие наблюдения снимает только его подписку. Stop последнего
потребителя прекращает FB штатной командой. Сохраняются отдельные проверки свежести
данных и состояния worker. Нельзя просто удалить watchdog или бесконечно обновлять
его из скрытого окна.

Потеря FB снимает зависимые аналоговые жесты. Цифровое удержание не протухает только
из-за отсутствия новых key events: отмена привязана к disconnect/session/loss, а не
к тайм-ауту аналогового измерения. Потерянные переходы и переполнение очереди дают
явную остановку соответствующего источника, а не скрытый пропуск key-up.

## Источники без перепрошивки

1. **Цифровой Windows InputSource:** Raw Input с фоновым получением, сопоставлением
   источника общему USB-устройству IO и фильтром поколения. Main/consumer интерфейсы
   обычного ввода отличаются от vendor MI_02, нельзя сравнивать только одну HID-строку.
   [Raw Input](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input).
2. **Штатный FB:** существующий transport и парсер, после приёмки физической карты,
   полного хода, отпускания, многоклавишного ввода и влияния simulation на обычный ввод.
3. **Назначенный HID-маркер:** возможный мост Main/Fn/DKS/макрос → редкий код → action.
   Проверить поддержку F13…F24 на IO и не обещать их невидимость для приложений.
4. **События программ/контекста/сервисов:** отдельные EventProvider, не USB-команды.
   Требуемый источник разрешений и платформенная реализация явно определяются.

Нормализованный цифровой код после remap может не идентифицировать физическую
клавишу. Fn и исходная глубина из него не восстанавливаются. Наблюдение и подавление
исходного ввода — разные capabilities. Маркировать собственную генерацию ввода и
проверить исключение рекурсии на выбранном источнике; не считать один timestamp
доказательством происхождения.

## Штатное назначение как триггер помощника

Кандидат для отдельной приёмки: DKS/MT/Main/Fn выдаёт выделенный keyboard usage,
цифровой InputSource получает его Down/Up, а каталог B исполняет действие. Для
«достигнуть порога → запустить команду» это может заменить непрерывный analog-поток.
Политика выбора — [ADR-0008](../docs/adr/0008-stock-first-delivery.md), все сценарии —
[матрица](../docs/FEATURE_MATRIX.md). Новых DTO и готового маршрута пока нет.

F13…F24 — ограниченный набор кандидатов; поддержка IO и отсутствие конфликтов ещё
не проверены. Не превращать произвольный ActionRef/macro ID/media-код в один байт
`DksConfiguration.actions`. Источник узнаётся по устройству, а назначение — по
применённой таблице; событие после remap само по себе не называет физическую клавишу.
Штатный Fn может вообще не выходить в обычный ввод.

Для приёмки подготовить одну исходную настройку и конкретный diff, записать только
выбранное назначение с сохранением неизвестных полей, проверить readback, физические
Down/Up на всех нужных этапах, повтор, modifiers, слой, unplug и restore. Приложение
должно различать собственную генерацию и входной маркер. Отдельно проверить, что
получает обычное окно при работающем/выключенном B. Код не считается «невидимым».

Условия «добавить действие на глубине» и «заменить лёгкое действие глубоким» разные.
Для второго нельзя сначала выпустить PgUp, затем отменить его: нужен подтверждённый
stock-шаблон или отложенное решение B над выделенным назначением. Время ожидания
и поведение без помощника показываются в форме правила; отключение B не восстанавливает
назначение устройства скрытым SET. Снятие stock-привязки — обычный обозримый diff.

Если stock не выдаёт пригодный код, маршрут помечается неподдержанным; не подбирать
неизвестные DKS opcodes записью в клавиатуру. Это не блокирует цифровые действия
на известных сочетаниях. Для velocity/траекторий/gamepad по-прежнему нужен analog.
Глобальная замена исходного ввода — будущий необязательный adapter перехвата ОС;
Raw Input observer первой версии её не обещает.

## Процессы, макросы и команды

Встроенные приложения остаются готовыми элементами каталога. `ProcessAction`
добавляет выбранную пользователем программу и аргументы как отдельные поля.
Путь проверяется при сохранении и перед запуском; отсутствие файла или платформенного
варианта возвращает понятную ошибку. Использовать механизм запуска аргументов ОС,
не строку командной оболочки. `.cmd/.bat` и shell-сценарии относятся к ScriptAction,
а не маскируются под запуск обычного executable.

Результат «программа запущена» не означает завершение её работы. Отмена правила
после открытия Word не должна закрыть пользовательский документ. Для собственного
скрипта/worker жизненный цикл и завершение дочернего процесса задаются отдельно.
Очередь и повторный жест не должны незаметно запускать много экземпляров: политика
повтора/параллельности задаётся действию; неопределённый результат не повторяется
автоматически.

ActionDefinition сохраняет варианты Windows/Linux/macOS. Windows adapter реализуется
первым; неподдержанный вариант блокирует только зависимое действие. Shell-команда
Windows не используется на другой ОС. SendInput имеет ограничения целостности
процессов; обычный помощник не может обещать ввод во все повышенные приложения.
[Microsoft: SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput).

## Хранение и миграция

Существующий профиль v2 и локальные данные не теряются. При первом переносе в
ProfileRepository сохранить исходный экспорт/версию, проверить данные в Rust,
записать файл атомарно и подтвердить чтение. WebView после миграции использует этот
repository через IPC; двух независимых записывающих хранилищ не оставлять.
Runtime работает только с применённой версией, черновик остаётся неисполняемым.

Разрешение фонового запуска и автозапуска хранится в локальных RuntimePreferences,
не в импортируемом профиле. Автозапуск исполняет только ранее включённую пользователем
версию; повреждённая/неизвестная версия оставляет помощник остановленным с сообщением.
Отключение автозапуска удаляет регистрацию запуска, не конфигурацию клавиатуры.

Для перехода без большого переписывания: сначала repository с совместимым чтением
v2, затем lifecycle, затем цифровой InputSource и ProcessAction. Откат сохраняет
исходный JSON; старый EXE используется с отключённым новым автозапуском. Новые виды
действий не отдавать старой версии как молча исполнимые — нужна версия схемы/ошибка.

## Приёмка

- **Модель и fake adapters:** независимость UI и runtime, stop последнего потребителя,
  повторный start, конкурирующие apply/stop, отмена поколения, переполнение, stale FB.
- **Runtime без WebView:** правила работают дольше старого watchdog без UI polling;
  после stop ни таймеры, ни очередь не запускают действий.
- **Источники:** другая клавиатура не вызывает IO-правила; remap/consumer/повторы и
  собственный синтетический ввод не создают дубли/рекурсию; unplug очищает удержания.
- **ProcessAction:** пробелы/Unicode в пути, отдельные аргументы, отсутствующая
  программа, повтор и отказ. Unit/integration тесты используют тестовый исполнитель.
- **Настоящий Windows сеанс:** закрыть окно → действие; открыть из tray; второе
  открытие EXE; пауза; sleep/lock/reconnect; «Выход»; отдельная проверка автозапуска.
- **Нагрузка:** час работы, p50/p95/p99 event-to-action, размер очередей и память;
  измерения не заменяются обещанием одинаковой задержки на любой ОС.

Остановка фона не выполняет SET/калибровку/reset/OTA. Сохранение профиля, импорт и
подключение расширенной firmware сами по себе не запускают процессы.
