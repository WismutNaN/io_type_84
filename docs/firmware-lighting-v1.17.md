# Подсветка в IO White 1.17

Дата: 2026-09-14. Статически проверен официальный HEX с SHA-256 `8f5ef507771c6795258eb7521cfc1b46269a5b301548767ae87a3f1a83a50d45`. Это анализ файла, не дампа установленной flash. Изменений прошивки, пробных RGB-пакетов и перебора адресов на устройстве не было.

## Результат для продукта

В бинарнике есть временная запись цвета **клавиш** через `0x32`, с изменением RAM. Это кандидат для уведомления «T мигает голубым», музыки и собственных анимаций, рассчитываемых приложением. Пока не установлен способ освободить управление и вернуть штатный эффект без сохраняющего SET, поэтому канал не включён в приложение.

У **LED-полосы** собственные эффекты, состояние, десять логических позиций и отрисовка по внутреннему значению глубины. Эти позиции не достижимы через восстановленную таблицу клавиш `0x32`. Наличие штатного индикатора хода подтверждается кодом, но само по себе не даёт компьютеру произвольное управление полосой.

Ключи, полоса и служебные индикаторы сходятся в общий RGB-буфер. Для дальнейшей архитектуры нужна сцена с явной целью и разными capabilities поверхностей; [ADR-0006](adr/0006-actions-gestures-scenes.md) описывает уведомления и композицию. Загрузка анимаций во flash и дополнительные аппаратные слои не установлены. Редактор изменённой прошивки пока не имеет достаточной технической основы.

## Воспроизводимость

Начальные адреса AA/55 dispatcher и FB serializer найдены как подсказки в локальном внешнем `archive_data/reference_projects/HallJoy/docs/firmware/io-type84-magnetic/DEEP_REVERSE.md`. Они независимо сопоставлены с собственным экземпляром официального HEX. Выводы ниже опираются на декодированные инструкции/таблицы этого HEX, а не на утверждения референса. Код референса в продукт не переносился.

Собственный [анализатор](../tools/analyze_lighting_firmware.py) проверяет точный хеш и Intel HEX, извлекает карты, адреса FUNC, дизассемблирует выбранные области с literal pool. [Отчёт](evidence/firmware-lighting-analysis.json) содержит результат. Список команд и трактовки RAM в отчёте — аннотации ручного анализа; скрипт не является автоматическим доказательством всех побочных эффектов.

## AA/55 и временный RGB

| Участок | Наблюдение |
|---|---|
| `0xD7C4` | Обработчик vendor-пакета; копирует 64 байта, меняет AA на 55 и разбирает команду |
| GET `0x10…0x18`, `0x1C` | Явные ветки GET; `0x1B` отсутствует |
| SET `0x21…0x28` | Явные ветки SET; `0x2A`, `0x2B`, `0x2D` отсутствуют |
| `0xDAF2…0xDB2C` | Ветки 64/65 и 66/67; 60/68 не реализованы здесь |
| `0xDB32` → `0xDCC8` | Команда 32: поток индивидуальных цветов |
| Команда 33 | Достигает общего ACK с эхом, не сериализует текущие RGB |

Это объясняет прежние результаты GET `1B` (тайм-аут) и `33` (эхо). Общий SDK содержит команды, не реализованные этой прошивкой. ACK неподдерживаемого запроса не подтверждает выполнение.

Handler `0xDCC8…0xDD36` берёт `floor(request[2] / 4)` четвёрок начиная с `request[8]`: `[matrixSlot, channel0, channel1, channel2]`. Адрес слота преобразуется таблицей по `0x152D5`; значение `120` означает пропуск. Первые 128 элементов таблицы содержат ровно по одному адресу `0…83`, остальные — пропуски. Например, физический T: slot 37 → render 37; PgUp: 105 → 16; PgDn: 108 → 47. Это адреса разных пространств, а не взаимозаменяемые номера клавиш.

Каналы записываются в массивы `0x20005514`, `0x20005592`, `0x20005610` с шагом 126. Вычисление канала: `floor(((channel × brightnessByte × 255) >> 16) / 6)`, яркость берётся из `0x200002C9`. Порядок физических RGB и зависимость воспринимаемой яркости требуют измерения. Handler устанавливает RAM-флаги `0x2000036B = 1`, `0x2000009A = 0x32`; вызовов функций внутри него нет. В отличие от SET `23`, здесь не виден вызов сохраняющей процедуры `0x3630`.

Этот локальный анализ поддерживает гипотезу временного канала, но не доказывает отсутствие отложенной записи из других задач firmware. Также не установлены максимальная частота кадров, восстановление эффекта и сосуществование с другими configurator-клиентами. Индекс не ограничивается 128 внутри handler: значения за таблицей могут читать посторонние данные. Нельзя проверять панель перебором адресов или переносить сюда размеры другой модели.

## LED-полоса

| Структура / функция | Смысл |
|---|---|
| `0x155BB` | 10 пар одинаковых индексов: 93, 93, 92, 92 … 84, 84 |
| `0x155CF`, `0x155D0` | Значение 10; число логических позиций соответствующих циклов |
| `0x20005D8E`, `0x20005D98`, `0x20005DA2` | Три локальных канала по 10 элементов |
| `0x20005DAC` | Массив интенсивности/огибающей |
| `0x200002F0` | База состояния панели |
| `0xE540` | Обновление эффекта; развилка штатных режимов и режима глубины |
| `0xEB60` | Отрисовка заполнения по глубине |
| `0xEEA0` | Композиция локального света в общий RGB-буфер, включая служебные наложения |
| `0x13028` | Вывод 126 элементов общего буфера через `0x6C90` |

Число 10 описывает логические позиции кода, не измеренное число корпусов LED или их физическое направление. Нужна корреляция с полосой владельца. UI пока использует условную пиктограмму.

Отрисовка глубины читает byte `0x20000108` через `0x3A84`, сравнивает его с таблицей по `0x15603`: `10, 20, 30, 40, 50, 60, 70, 80, 90, 95`. Достигнутые сегменты получают цвет и огибающую `0xF0`, остальные гасятся. Шкалу нельзя пока называть миллиметрами или процентами: производитель этого значения и его выбор среди одновременно нажатых клавиш ещё не прослежены полностью.

В 128-элементной карте клавиш нет индексов 84…93. Передача этих чисел как matrixSlot не адресует полосу: получится другая клавиша или пропуск. Прямой host setter для локальных массивов полосы не найден.

## Связь с Fn+G / Fn+K / Fn+L

Назначения страницы `0x0D` проходят `0x51AE` → `0x5482` → `0x3738`. Последняя функция выбирает ветку через таблицу относительных указателей по `0x374C`.

| Назначение профиля | FUNC | Указатель → handler | Статический эффект |
|---|---|---|---|
| Fn+G | 87 | `0x38A8` → `0x6A14` | Включает флаг `0x20000092`, переключает `0x20000093` между 1 и 2 |
| Fn+K | 91 | `0x38B8` → `0x67F4` | Цикл состояния наложения `0x20000082`, 0…3 |
| Fn+L | 27 | `0x37B8` → `0x68E4` | Цикл `0x2000030A`, сброс режима RT, инициализация штатного эффекта |

Пути K/L обращаются к общей процедуре `0x54C4`. Уточнение 2026-09-14: она формирует
16-байтовый блок с маркером `A5` и вызывает writer `0x3630` по логическому адресу
`0x8200`. Это статическое доказательство пути сохранения panel/options во flash.
Полный состав блока и физическая проверка сохранения после снятия питания остаются
отдельной работой. Нельзя использовать эту процедуру для каждого кадра анимации.

В OpenAula найден готовый C renderer собственного RGB-эффекта, вызываемый после
штатного обновления. Он выбран как референс будущего расширения; его 126-слотовые
буферы/адреса не подходят напрямую к IO, отдельная полоса не реализована.
[Применимость](reference-projects/OPENAULA.md), [база firmware/recovery](firmware/README.md).

## Следующие проверяемые шаги

1. Проследить производитель `0x20000108`, выбор глубины при нескольких клавишах и условие выхода из host RGB. Установить все места чтения/сброса его RAM-флагов.
2. После этого подготовить один ограниченный эксперимент RGB на свободной клавише: исходный snapshot, один цвет, визуальное наблюдение, выход и сверка конфигурации. Не использовать сохраняющий SET на каждый кадр.
3. Только с доказанным выходом добавить renderer временных сцен, TTL уведомления, приоритеты и восстановление базового эффекта. Музыка использует тот же renderer с другим источником данных.
4. Для полосы сначала проверить штатные режимы и направление логических позиций; продолжить поиск входного канала. Если setter отсутствует, не обещать произвольные уведомления на полосе без изменения firmware.
5. К патчам firmware вернуться лишь после определения MCU, карты flash, образа bootloader и реального способа восстановления. Текущая работа не включает прошивание.
