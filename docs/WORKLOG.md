# Журнал выполненных работ

## 2026-09-14 — причина двойного PgUp и выбор следующего сценария

Владелец сообщил о совместном PgUp и громкости на глубоком нажатии. Прочитаны
GestureEngine, DepthActions и service/action_runtime: независимые пороги добавляют
действие к аппаратному вводу, исключающего выбора нет. Это соответствует жалобе;
нового аппаратного эксперимента и измерения FB не выполнялось.

В [automation](../modules/automation.md#exclusive-depth) записан предложенный цикл:
лёгкое действие на отпускании, глубокая ветка окончательно отменяет лёгкую до нового
цикла. Отдельное условие реализации — владение исходным вводом. Уточнены STATUS/PLAN:
сначала принять этот сквозной сценарий, поддерживая общий профиль и adapters stock/
extension. Новое поведение не объявлено реализованным или выбранным пользователем.
Проверены код, первичные QMK/Microsoft документы, ссылки и `git diff --check`.
Runtime, устройство и профиль не менялись; сборка для документации не требуется.

**Решение:** [ADR-0008](adr/0008-stock-first-delivery.md) продолжает принятые три

зависимость действий по порогу от полного analog, но ещё не проверен на IO.
Сверены байтовая модель DKS и выбор keyboard usages в редакторе; произвольный macro ID
в этот формат не добавлялся.

**Уточнения:** дополнительное действие и замена исходного ввода имеют разную семантику.
Отдельный перехват ОС может закрывать часть Tap Dance/Combo/Overrides без firmware;
Raw Input сам её не предоставляет. Проверены первичные документы Microsoft Raw Input,
RegisterHotKey, LowLevelKeyboardProc/KBDLLHOOKSTRUCT и SendInput; ссылки в матрице.

firmware. Большой черновик обращения переведён в архив: он не выдан за фактически
отправленный владельцем текст. README остаётся в отдельной контрольной точке `2cb00ff`.

**Проверки:** идентификаторы 76 строк уникальны, локальные ссылки/якоря проверены,

## 2026-09-14 — ресурсы SN34F280 и границы расширения

**Получено:** полный официальный Sonix SN34F280 manual v1.7 от 2025-05-08,
569 страниц. Рабочий URL `/webapi/fl219527/SN34F285_V1.7_EN.pdf` найден через
ссылку на исходный datasheet; старые `/download/file?...` возвращали HTML/ошибки.
PDF проверен по сигнатуре/размеру/SHA-256. Полный текст извлечён, таблицы на
с. 30, 531, 546, 559, 560 дополнительно просмотрены как изображения.
[Источник и воспроизведение](evidence/chip-feasibility.json).

**Новые факты документации:** до 192 МГц; точка ADC 1 MSPS при заданных timings;
MM включает 8 КиБ Boot и 504 КиБ User, SM — 2 КиБ. CS1→CS0 стирает User,
CS3→CS0 также Boot; BOOT зависит от Code Option. Flash program/erase могут
останавливать CPU; runtime-сцены/пороги нельзя реализовывать сохраняющим SET
на каждый tick. Это свойства семейства, не прочитанный статус нашего экземпляра.
Зафиксированы расхождения SVD/manual по CHIPID и опечатки адресов/CS/customer page.

**Результат для продукта:** [оценка MCU](firmware/chip-feasibility.md) сопоставляет
Protection, DKS/RT/MT/TGL/SOCD, QMK-подобные автоматы, условные макросы, Analog SDK,
gamepad и свет с A/B/C. [Новые cases](firmware/case-coverage.md) сохранены как
каталог требований; их примеры не объявляются функциями IO. Проверены первичные
источники QMK, Wooting, SteelSeries и Microsoft. Описаны состав комплекта исходников,
сложность API/overlay/full rewrite и необходимый стенд. Подготовлен
[проект запроса IO/OEM](firmware/manufacturer-request.md), никому не отправлен.

**Проверки:** совпали шесть хешей/размеров источников (manual, DFP/PDSC/SVD и два
case-файла), PDSC-модели/частота/RAM; проверены 11 расчётных соотношений бюджета,
301 локальная ссылка, 15 footnotes и номера страниц PDF. `git diff --check` пройден.
Приложение и контракт IPC не менялись; сборка/аппаратные тесты для этой группы
документации не запускались. PDF, текст, рендеры и исходные cases остаются вне Git.

**Граница результата:** семейство определено с высокой уверенностью, точная
маркировка MCU/PCB отсутствует. Clock tree, свободная память, полный analog,
RDP/BOOTPINEN, backup и recovery конкретного IO не установлены. Никаких HID/ISP,
изменений настройки/прошивки или внешних сообщений в этом этапе не было.
Следующий шаг C: комплект производителя и проверяемый recovery, затем узкий API.

**Контрольная точка:** `docs: assess SN34F280 capabilities and recovery constraints`.

### Систематизация по трём уровням интеграции
