## 2026-09-14 — настольные редакторы и UX

**Реализовано:** общая схема из 84 клавиш, группы/поиск/выбор протягиванием, base/Fn, клавиатура/media/мышь/колесо/CB/FUNC, RT, 21 эффект, индивидуальные цвета/градиент, редакторы аппаратных макросов и MT/TGL/RS/SOCD/DKS, общие настройки. Черновик с групповой отменой/возвратом, человекочитаемая сводка перед записью, recovery. Собственные профили v1, локальное хранение до 40 документов, JSON import/export; частичный импорт IO Vision с отчётом. Уточнены mouse bitmask, macro repeat и WholeTravel по официальному bundle. В профиле найдены штатные функции панели 27/87/91, добавлен каталог назначений.

**UX-проверка:** настоящий release WebView открылся, Vue → Tauri → Rust прочитал IO 1.17. Выбор A показывает данные снимка. Запущено наблюдение: две позиции с 0,18 мм и ограниченная история появились в UI; закрытие завершило сеанс. В отдельном локальном примере проверены создание градиента для WASD, отмена всего градиента одним действием и возврат. После визуальной проверки усилен контраст, увеличены подписи, убрано дублирование обычных назначений на keycap; в узком окне инспектор переносится вниз. При переходе между разделами сбрасывается прокрутка, диалог удерживает фокус. Не тестировали каждое физическое advanced-поведение.

**Автоматические проверки:** `npm run check` прошёл: 5 TS-тестов (повреждённый JSON, пары/адреса, иммутабельность черновика, градиент, нулевые RT сайта), 11 Rust-тестов (8 platform/2 core/1 упаковка), TypeScript/Vite, rustfmt, Clippy. Release EXE собран через `desktop:build`. Пользовательский `profile.json` проверен адаптером без записи: 84 нулевых порога и 97 отсутствующих userKey сохраняют исходные значения.

**Ограничения:** FB физически не откалиброван, наблюдались два адреса вместо проверки всех клавиш; возможны шумовые события истории. Текущий RGB дал эхо. Прямая топология/настройка панели, playback всех режимов, сохранение после снятия питания и полный паритет сайта остаются открыты. [Покрытие](EDITOR_IMPLEMENTATION.md), [дальнейшие проверки](STATUS.md). UI-пример и сохранение JSON не меняли устройство. Аппаратные изменения из предыдущей записи восстановлены.

**Контрольная точка:** `feat: собрать редакторы клавиатуры и локальные профили` (после `6886b8e`). README обновлён для GitHub; исследования, ADR и текущий статус вынесены в отдельные документы.

Заключительный smoke test: Vite остановлен, на 1420 нет listener, последняя release-сборка запущена заново и через UI прочитала 1.17. Окно оставлено открытым с пустым черновиком и выключенным наблюдением. [Сводка проверки](evidence/desktop-smoke.json). Ссылки между Markdown-документами проверены, битых относительных ссылок нет.

## 2026-09-14 — запись с обратным чтением и восстановлением

Реализованы один HID worker с ограниченной очередью, типизированный IPC, подготовка изменений по ревизии исходного снимка, проверка текущей конфигурации перед SET, raw-backup с flush до отправки и GET-сверка каждого блока. Неизвестные поля RT/общих настроек/цветов/DKS сохраняются; неизвестный формат макроса блокирует его перезапись. После ошибки операции не повторяются автоматически. Повторное подключение открывает новый handle.

Аппаратно проверены яркость `5 → 4 → 5`, назначения F12 в двух слоях, его RT и RGB, свободные записи макроса и DKS без привязки к клавише. Все шесть блоков второго эксперимента прочитаны обратно; исходные блоки восстановлены, итоговая ревизия полностью совпала. Первый тест подсветки выявил write-only маркеры FF/AA/55: ошибка readback исправлена, начальная яркость восстановлена, повторный цикл прошёл. [Подробное свидетельство](evidence/native-write-roundtrip.json).

Аппаратное исполнение макросов/RS/SOCD/MT/TGL/DKS и сохранение после снятия питания не проверены. Полные конфигурации/backup остаются вне Git. `npm run check` прошёл (8 platform + 2 core + 1 packaging Rust-тест, проверки TS, frontend, Clippy); последующие UI-изменения проверяются отдельно. Контрольная точка: `feat: добавить проверяемую запись конфигурации и восстановление`.

## 2026-09-13 — прошивка, профиль, LED-панель и Vial

**Выполнено:** по каталогу производителя скачан точный HEX White 1.17, написан самостоятельный анализатор Intel HEX без доступа к устройству. Изучен профиль пользователя. Отдельная LED-панель включена в требования и модель световых поверхностей. Проверена гипотеза Vial по сообщению бренда, исходникам GUI и повторному перечислению HID.

**Проверка:** контрольные суммы всех 5677 HEX-записей корректны, 90 728 байт в двух сегментах; шесть тестов анализатора прошли. Профиль содержит 84 клавиши и 128 RT/RGB-записей, но нулевые RT-пороги нельзя считать текущими аппаратными значениями. Найдены семь HID collections и ноль FF60:0061: штатный Vial GUI отфильтрует текущий IO White. Ролик бренда относится к Custom 68. Настройки устройства не изменялись.

**Ограничения:** MCU/OEM и команды панели не доказаны; пробная Thumb-дизассемблировка — признак архитектуры, не восстановленный исходный код. Vial не запускался, его команды не отправлялись. Отсутствие стандартного Vial-интерфейса не исключает частичное QMK-происхождение firmware. Прямое видео не просмотрено; подтверждение модели взято из публикации бренда.

## 2026-09-13 — AK820, Aether-HE и границы HFD-совместимости

**Выполнено:** разобраны два новых локальных референса, их идентификаторы, codec, размеры таблиц, RT, lighting, TFT, macro и исследовательские материалы. Проверены цепочка fpb → QMK/SonixFlasherC, официальный SN32F299 manual и ARM Cortex-M0 ISA. В коде сайта IO сопоставлены light box, side light, temporary RGB, simulation/FB и macro capacity. Точные локальные ревизии и файлы перечислены в [исследовании](REFERENCE_PROJECTS.md).

**Offline проверка:** собственный harness проверяет SHA-256 референсов, извлекает только рассмотренные чистые функции. Rust `build_frame` AK820 воспроизвёл 80/80 пакетов; Mini60 `build_table_read` — 79/79 обычных GET (68 с key IDs исключён). RT decode → encode совпал для 128 записей; parser Mini60 без отсечения padding дал бы 133. Stacks чужих приложений и Cargo build scripts не запускались. [Отчёт](evidence/reference-codec-comparison.json).

**Устройство:** `tools/probe_aux_lighting.py` сверил точный FF68 descriptor и GET info/identity 1.17, отправил GET `1B` на 24 байта. За 1000 мс ответ не получен. Скрипт остановился без повторов, GET `1D` пропущен, handle закрыт. Два HID Output reports являются запросами чтения; конфигурационных SET не было. [Сырые данные](evidence/aux-lighting-probe.json).

**Новые результаты:** общий framing подтверждён, но приложения не содержат модель IO; Mini60 имеет другие размеры RT/RGB и keymap write. Временный RGB `32` вопреки имени GET отправляет данные. В parser IO `55 FB` байты 2/3 означают keyValue/calibrationStatus, что совпадает с §12 HFD-документа Aether. Промежуточное утверждение о различии этих полей исправлено при финальной сверке. Raw macro capacity=37376, а экспортные 512 могут быть fallback сайта. Дизассемблирование reset IO показывает immediate Thumb-2 BIC/MOV; это не соответствует простой гипотезе Cortex-M0 SN32F299. Точный MCU/OEM и путь прошивки не установлены.

**Проверки:** 10 Python unittest прошли (6 HEX + 4 fail-closed границы probe); offline harness завершился без расхождений. JSON evidence и локальные ссылки новых документов проверены; `git diff --check` чист. Rust/Vue код не менялся; сборка desktop и ручной UI smoke test в этой итерации не повторялись.

**Ограничения:** тайм-аут не доказывает отсутствие команды/панели. SET, simulation, calibration, reset и OTA не запускались; прошивальщики и сторонние приложения не исполнялись. Совместимость framing/RT не доказывает firmware compatibility. Не переносили код референсов в продукт. Отсутствие лицензии у Aether зафиксировано для будущего переноса, анализ и самостоятельная реализация продолжаются.

**Контрольная точка:** коммит `research: проверить совместимость AK820 и Aether с IO White`.
