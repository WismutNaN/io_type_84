# Референсный профиль сайта

Дата исследования: 2026-09-13, реализация обновлена 2026-09-14. Пользовательский файл `archive_data/profile.json`, 101 367 байт, SHA-256 `1aba54dbe66419b88cbcfd598db54f4e20fdc8d7536fce0140b52e6716436328`. Частичный импорт реализован в `src/features/editor/io-vision-profile.ts`.

Полный профиль остаётся в игнорируемом архиве. [Сводка](evidence/profile-reference-summary.json) содержит поля, размеры и технические параметры без полного набора пользовательских назначений и имени профиля.

## Структура

Корень содержит `deviceId` и `profile`. Идентификатор `3141:32982:IO Type 84 Magnetic White` соответствует USB `0C45:80D6`; в `deviceInfo` указана версия 1.17.

| Поле profile | Наблюдение |
|---|---|
| deviceInfo | 20 полей информации о модели и возможностях |
| gameModeInfo | 13 полей общих настроек |
| keyList | 6 рядов, 84 физических клавиши |
| fnKeyList | 6 рядов, 84 клавиши; 71 запись с userKey |
| ledEffect | 15 полей; mode=11, brightness=5, speed=3 |
| customLedData | 128 записей RGB, в этом файле все RGB равны 0 |
| magneticAxisRT | 128 записей; triggerKeyStroke во всех равен 0 |
| magneticAxisRTConfig | currentModeName=custom; customModeRT также содержит 128 записей с нулевым triggerKeyStroke |
| macroDataList / magneticAxisDKS | Пустые массивы |
| wheelKeys | Пустой массив |
| profileName | Имя профиля пользователя |

В `keyList` нет `userKey`. Это не означает отключение всех клавиш: внешний формат может опираться на исходное назначение. Пустые макросы и DKS описывают данный профиль, а не отсутствие функций в прошивке.

## Ограничения интерпретации

Ранее непосредственное GET-чтение показало, например, порог A=2,23 мм и ledEffect.mode=20. В этом экспорте пороги нулевые, эффект другой. Файл может отражать иной момент, черновик или значения по умолчанию интерфейса. Причина не доказана. Его нельзя выдавать за актуальный аппаратный снимок или автоматически применять нули ко всем клавишам.

Отдельных полей `lightBoxData`, `sideLightData` или `ledPanelData` нет. Это не опровергает наличие физической [LED-панели](LED_PANEL.md): экспорт может сохранять только часть настроек.

`deviceInfo.macroSpaceSize=512` не является прямым измерением памяти: сайт подставляет 512, если не включён модельный флаг чтения capacity. В сохранённом HID payload соответствующие байты дают 37376. Полезная ёмкость не установлена; [разбор](PROTOCOL.md#информация). Импорт не должен превращать UI fallback в аппаратную capability.

## Реализованный импорт

Адаптер требует исходную конфигурацию, проверяет модель, шесть рядов/84 уникальных физических адреса, размеры RT/RGB и типы полей. Поддерживает известные назначения/часть FUNC, ненулевые RT, цвета, эффект, частоту и мёртвые зоны. Отсутствие userKey сохраняет текущее назначение. Нулевые/слишком малые пороги пропускаются с отчётом. Каталоги макросов/DKS из сайта, неизвестные функции и остальные поля не переносятся; пустые массивы не трактуются как команда удаления. Блоки, которых нет, не обнуляются.

На пользовательском файле подтверждены 84 пропущенных нулевых порога и 97 позиций без userKey. Импорт создаёт только Draft; ничего не отправляет устройству. Unknown FUNC reset/Mac не записываются, известные функции света/панели перенесены в allowlist. Свой профиль v1 поддерживает полный набор реализованных DTO, включая макросы/DKS; неизвестные raw-поля устройства принадлежат исходному snapshot/recovery, не переносятся между устройствами через DTO.

Внешний формат принадлежит адаптеру `io_vision_profile`, а не доменному core. Импорт должен определить модель, проверить размеры и адреса, сохранить неизвестные значения и построить Draft с предупреждениями по неоднозначным полям. Отсутствующие блоки не заполняются нулями. Применение требует обычного ChangePlan и исходного снимка по [прикладному модулю](../modules/application.md).

Собственный профиль уже имеет schemaVersion=1, name, savedAt и KeyboardSnapshot. Правила и независимые сцены пока не входят в схему. [Хранение и IPC](DEVELOPMENT.md).
