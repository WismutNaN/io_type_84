# Интерфейс и сценарии

<a id="integration"></a>
## Выбор глубины интеграции

Целевой UX по [ADR-0007](adr/0007-integration-levels.md); настройки фоновой работы
и расширение устройства в текущем EXE ещё не реализованы.

По умолчанию пользователь попадает в штатный редактор. В «Настройках приложения»
доступны «Работать в фоне» и отдельно «Запускать при входе в систему». Первая
управляет помощником, вторая — его локальным автозапуском. Оба выключены при первом
запуске. Пауза и состояние активного профиля доступны из tray и окна. Выход завершает
процесс, остановка помощника сохраняет аппаратные назначения.

В карточке назначения достаточно «Клавиатура» / «На компьютере»; зависимость
«Требует расширения устройства» показывается только для конкретной недоступной
функции. Технические причины раскрываются по запросу. Три отдельных редактора или
обязательный экран выбора A/B/C не нужны. Каталог единый по восприятию, но аппаратные
макросы и команды ОС сохраняют разные операции и ограничения. Место исполнения
не меняется молча.

| Состояние | Представление |
|---|---|
| Штатная клавиатура, фон выключен | Аппаратные настройки; действия компьютера показывают зависимость от помощника |
| Фон работает, окно скрыто | Tray: открыть, пауза/продолжить, выход; состояние активного профиля |
| Источник/действие не готовы | Причина рядом с зависимым правилом; остальные настройки доступны |
| Не хватает памяти макросов | Использовано/доступно в проверенном диапазоне; сокращение или явный перенос в программный макрос |
| Импорт из другой ОС | Сохранить варианты; указать отсутствующий исполнитель, не подставлять Windows-команду |
| Полоса требует нового API | Локальный preview доступен; физический вывод не обозначается работающим |

Подключение устройства и создание аппаратного макроса не предлагают перепрошивку.
Расширение firmware рассматривается отдельно после подготовки совместимости и recovery.
[Примеры выбора](INTEGRATION.md#как-это-выглядит-для-пользователя).

Актуальная реализация: 2026-09-14. [Решение](adr/0005-editor-interaction.md), [технический контекст](../modules/editor-interaction.md), [покрытие функций](EDITOR_IMPLEMENTATION.md). Это рабочий UI, а не макет планируемого shell.

## Компоновка

При ширине от 1280 px клавиатура находится слева, редактор справа. Основное назначение раскрывается по запросу, чтобы не закрывать дополнительные действия длинным каталогом. Справа прокручиваются только настройки; выбранная физическая клавиша остаётся на виду. В окне 960×700 редактор переносится под клавиатуру. Его действия доступны вертикальной прокруткой. Форма не получает горизонтальный overflow. В браузере на ещё меньшей ширине схема сохраняет двумерную геометрию и прокручивается отдельно; остальные формы перестраиваются в колонку.

Навигация: «Клавиатура», «Свет», «Каталог», «Профили», «Параметры». В клавиатуре три инструмента: «Действия», «Срабатывание», «Поведение». Применение, сохранение и undo/redo находятся в постоянной нижней строке. Убраны hero, декоративные подзаголовки и повторяющийся футер.

## Состояния клавиши

| Состояние                                           | Отображение                                                         |
| --------------------------------------------------- | ------------------------------------------------------------------- |
| Выбрана для редактирования                          | Синяя обводка, `aria-pressed`                                       |
| Физическое движение от 0,30 мм                      | Зелёная подложка, независимая от обводки                            |
| Свежее измерение                                    | Зелёная полоса 0–3,20 мм; малые движения тоже видны                 |
| Данных нет / старше 600 мс / наблюдение остановлено | Полоса гаснет, числовой показатель «—», выбор сохраняется           |
| Переназначена                                       | Основная подпись — действие, маленькая подпись — физическая легенда |
| Глубокое действие компьютера                        | Отдельная строка `↓ Vol +` и т. п.                                  |
| Заданный цвет                                       | RGB из черновика                                                    |
| Текущий цвет неизвестен                             | Штрих; никаких сгенерированных «живых» цветов                       |

Таймер интерфейса увеличивает возраст кадра независимо от IPC. Потерянный release размыкает историю после 600 мс. История показывает только целые плитки по ширине, без scrollbar; хранится не более трёх таких областей, фильтр движения 0,30/0,15 мм убирает ранее наблюдавшийся шум 0,18 мм. Это не порог RT, не HID key-down и не измерение силы в граммах.

## Частые сценарии

| Сценарий                      | Шаги                                                                                                     |
| ----------------------------- | -------------------------------------------------------------------------------------------------------- |
| Обычное назначение            | Выбрать клавишу → тип/действие → «Назначить в черновике»                                                 |
| Ход группы                    | Ctrl + клик / протянуть / WASD / Все → «Срабатывание» → шкала или пресет → добавить в черновик           |
| Глубокий PgUp                 | Выбрать PgUp → «Громче» (предвыбрано) → при необходимости передвинуть порог → «Добавить в черновик»       |
| Глубокий PgDn                 | Выбрать PgDn → «Тише» (предвыбрано) → добавить в черновик                                                          |
| Запустить действия компьютера | Черновик → «Применить» → проверить жесты и включение исполнения                                |
| DKS                           | Выбрать клавишу → «Поведение» → этап движения → шкала и «нет / касание / удержание» для каждого действия |
| Свет                          | Эффект и шкалы либо выбранная группа и цвет/градиент → добавить в черновик                               |
| Применить                     | Нижняя кнопка → конкретный список отличий → запись с backup и обратным чтением                           |
| Профиль                       | Сохранить на компьютере или импорт/экспорт JSON; это отдельное действие от Apply                         |

Редактирование меняет черновик. Применение заменяет исполняемую версию; общая кнопка «Остановить жесты» действует из любого раздела. Условие исполняется один раз после достижения порога всеми клавишами и заданного удержания; для повторения требуется возврат минимум на 0,60 мм (или до нуля у малого порога). После старта/потери потока сначала нужен реальный отсчёт выше границы возврата. Это защищает от повтора зажатой клавиши. Работает на физическом слоте независимо от Fn. Нормальное аппаратное PgUp/PgDn не подавляется. Без открытого приложения/наблюдения программное действие не выполняется.

## Язык, тема, доступность

Русский и английский; предпочтение сохраняется отдельно от конфигурации устройства. Светлая, тёмная и системная темы используют общий набор токенов. Основной текст 14 px, вспомогательные подписи 12–13 px; подписи клавиш масштабируются в пределах геометрии. Тексты назначений имеют короткие формы PgUp/PgDn и полное доступное описание. Системный стек Segoe UI / system-ui, без загрузки шрифтов из сети.

Tab и видимый фокус; стрелки перемещают фокус по схеме, Enter выбирает, Space расширяет группу. Ctrl+Z / Ctrl+Shift+Z отменяют/возвращают группу, Ctrl+S сохраняет профиль. Сочетания редактора не перехватывают ввод в поле. Модальные проверки удерживают фокус; Escape закрывает их. Анимации смены состояния/глубины и предпросмотр света; reduced motion отключает переходы и по умолчанию ставит предпросмотр на паузу.

## LED-панель

Положение подтверждено владельцем: под Del/PgDn, над стрелками. Нейтральная пиктограмма показывает место поверхности. Количество нарисованных столбиков не является числом физических LED. Прямое управление, фактические текущие цвета, частота обновления и топология пока неизвестны. [Исследование](LED_PANEL.md).

## Расширение UX

Расширение проходит через структуру «условие → действие → исполнитель», а не через отдельную постоянную страницу на каждый новый тип функции.

| Возможность                                 | Следующий редактор / зависимость                                                                                 |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Double tap и взаимоисключающие пороги | Общая карточка условия, временная шкала и предпросмотр результата; учитывать задержку одиночного действия        |
| Условия по приложению/слою                  | Дополнительные фильтры внутри правила, обозначение активного профиля                                             |
| Программные слои                            | Список рядом с Main/Fn; явное место исполнения, переключение без записи flash                                    |
| Скрипты / расширения                        | Каталог действий со схемами параметров и правами; проверка/остановка, отдельный sandbox adapter                  |
| Анимации клавиш / панели                    | Выбор поверхности → сцена → временная шкала; реальное выполнение только после подтверждения transport capability |
| Профили с правилами и сценами               | Жесты и каталог уже в v2; сцены добавятся следующей версией документа                         |
| Фоновый помощник                            | Tray и жизненный цикл, доступная остановка всех действий; текущая версия ограничена открытым приложением         |

Неактивные возможности не занимают навигацию пустыми экранами. Добавлять их вместе с рабочим сценарием и проверкой. Редакторы форм используют явное добавление в черновик; незавершённая форма при смене клавиши пока не является сохранённым изменением. Автосохранение незавершённых форм/черновика и смешанные значения групп — следующий этап, не выдавать их за реализованные.

## Проверка

`npm run test:ui`: Playwright + установленный Edge, 1480×908 и 960×668 CSS px (соответствуют окнам с системной рамкой), 84 клавиши, PgUp/PgDn, RU/EN, light/dark, все редакторы, отпускание и зависший IPC. Тестовая телеметрия используется только внутри теста через mock IPC; в приложении нет скрытого режима имитации. Это не заменяет физическую проверку магнитных датчиков.

## Предпросмотр света и история

`lighting-preview.ts` — детерминированная иллюстрация характера 21 эффекта; `use-lighting-preview.ts` управляет часами и реакцией. Предпросмотр не воспроизводит firmware renderer побайтно и не сообщает фактический RGB. Три источника отображения: предпросмотр / заданный индивидуальный цвет / подтверждённый текущий RGB. На обеих страницах editor справа от 1280 px, ниже при меньшей ширине. История использует целое число плиток по ширине; backend хранит максимум три таких области, без сохранения на диск.

## Каталог и жесты

В «Каталоге» две вкладки: действия компьютера и аппаратные макросы. Название, команда и шаги редактируются в отдельном месте; параметры ОС раскрываются по запросу. Клавиатура предлагает готовое действие для выбранной клавиши/сочетания, шкалу глубины, пресеты неполного/полного хода и удержание. Можно добавить несколько жестов. Подпись на клавише показывает первое действие и число остальных. Удаление используемого действия заблокировано, пока на него ссылаются жесты.

Программные условия входят в undo/redo, локальный профиль и экспорт. Изменение каталога меняет все назначения по ID. Независимые уровни могут выполняться последовательно при полном ходе — это явно показано в форме. Автоматический выбор только одного действия и double tap пока не реализованы. [Контракты](../modules/action-catalog.md), [проект сцен и расширений](adr/0006-actions-gestures-scenes.md).


## Исключающий выбор PgUp/PgDn

В инструментах действий доступны «Лёгкое / глубокое» и «Добавочное действие».
Первый показывает две ссылки каталога и шкалу глубокого порога, лёгкий порог
раскрывается отдельно. Подписи на клавише показывают обе ветки. Конфликтующие
добавочные жесты не работают параллельно; форма сообщает об их замене.
Черновик, undo/redo и профиль включают весь выбор. На Apply отдельно показывается
временная передача обеих аппаратных раскладок приложению и восстановление при
остановке. [Полный контракт](../modules/exclusive-depth.md). Старое описание
глубокого PgUp как добавочного действия выше относится к независимым жестам.
