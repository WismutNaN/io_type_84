# Возможности и уровни интеграции

Актуально: 2026-09-14, IO Type 84 Magnetic White `0C45:80D6`, firmware 1.17.
Это единая карта целей и результатов исследования. Точные форматы и доказательства
остаются в профильных документах, перечисленных внизу. Решение о трёх вариантах
использования принято по запросу владельца; [ADR-0007](adr/0007-integration-levels.md).

Для новых сценариев Protection, Analog SDK/gamepad и составных правил:
[оценка MCU](firmware/chip-feasibility.md) и [покрытие cases](firmware/case-coverage.md).
Она различает потенциал семейства, stock-кодек и реальные измерения IO.
Динамические аппаратные параметры должны иметь volatile-путь: flash не подходит
для обновления на каждое нажатие/кадр. [Ресурсы и безопасность Sonix](firmware/sonix-manual-safety.md).

## Три варианта использования

| Вариант | Что делает пользователь | Где исполняется поведение | Нужен ли постоянно запущенный помощник |
|---|---|---|---|
| **Настроить клавиатуру** | Открывает редактор, задаёт параметры, записывает их в устройство | Штатная прошивка | Нет для аппаратных назначений и макросов |
| **Добавить помощника** | Включает фоновую работу и при желании запуск при входе в ОС | Штатная прошивка + приложение в пользовательском сеансе | Да, для действий компьютера |
| **Расширить устройство** | В будущем устанавливает совместимое расширение прошивки | Дополнительная логика устройства; при необходимости тот же помощник | Для уведомлений/интеграций — да; для автономных функций firmware — нет |

Это не три обязательных последовательных шага. Конфигуратор должен быть полноценным
без помощника и перепрошивки. Фоновый помощник должен давать полезные функции на
штатной firmware. Расширение firmware не заменяет приложение для работы с ОС.
У одного профиля могут одновременно быть аппаратные и программные назначения.

Настройка через SET меняет параметры/таблицы штатной firmware. Прошивка меняет
исполняемый код устройства. Аппаратные макросы относятся к **настройке**, хотя их
данные записываются в память клавиатуры.

## Как читать степень готовности

- **Запись проверена:** реальные SET → GET → восстановление совпали. Это отдельно
  от воспроизведения функции и сохранения после отключения питания.
- **Есть код:** реализованы редактор/codec/runtime и программные проверки; физический
  сценарий может оставаться непроверенным.
- **Анализ:** найден путь в точном HEX/SDK; аппаратной проверки нет.
- **Прототип:** изолированная проверка модели или ARM routines, не функция устройства.
- **Запланировано:** функция и её граница определены, реализации ещё нет.

Отсутствие исследованной команды означает «не найден поддерживаемый путь», а не
доказательство невозможности для всех прошивок и аппаратных ревизий.

## A. Максимум штатной клавиатуры

| Возможность | Что можно настраивать | Текущий результат / оставшаяся проверка |
|---|---|---|
| Назначения Main и Fn | Клавиши, media, мышь, сочетания, известные FUNC | Есть редактор; запись двух назначений F12 проверена; физическое выполнение ещё не принято |
| Ход и Rapid Trigger | Порог, RT, доступные флаги; одной клавише или группе | Есть код; параметры F12 записаны/прочитаны/восстановлены |
| Производительность | Частота опроса и мёртвые зоны | GET и codec есть; SET 21 и фактические режимы не проверялись |
| RGB клавиш | Штатные эффекты, яркость, скорость, направление, цвет, статический градиент | Есть редактор; яркость и цвет одного слота прошли запись/восстановление |
| Аппаратные макросы | Последовательности клавиатуры/мыши, задержки и поддержанные варианты повтора | Короткий несвязанный макрос записан в устройство и прочитан обратно; исполнение/сохранение после питания не проверены |
| Продвинутые назначения | DKS, MT, TGL, RS, SOCD в пределах штатных форматов | Есть формы/codec; запись свободного DKS проверена, физическая семантика режимов ещё не принята |
| Штатные режимы полосы | Переназначить FUNC 27/87/91: эффект, глубина, наложение | Связь профиля и handlers подтверждена анализом; прямого редактора параметров полосы по GET/SET нет |
| Локальные профили | Сохранить конфигурацию, каталог, правила; импорт/экспорт | Собственная схема v2; частичный импорт сайта. Локальные профили не равны аппаратным слотам |

Цель A — открыть **все подтверждённые параметры действующей firmware**, включая
макросы и сложные штатные режимы, а не ограничить продукт простым remap. Для ещё
неизвестного параметра сначала определить кодирование, исходное значение и способ
проверки; наличие формы в общем SDK само по себе не даёт capability IO.

Ограничение writer макросов сейчас **512 байт вместе с каталогом 400 байт** —
предел нашей проверенной реализации, не установленная полная ёмкость устройства.
Каталог из 100 смещений не означает 100 длинных макросов. Raw поле 37376 из info
не принято за доступный объём памяти. Следует сначала исследовать адреса/границы
штатного хранилища; увеличение лимита не объявлять задачей перепрошивки заранее.
Неизвестные макросы и резервные данные сохраняются.

Снятие питания ещё не тестировалось для изменённых блоков. До этой приёмки точная
формулировка результата — «записано и проверено чтением», а не «автономная работа
полностью проверена». Подробности: [покрытие](EDITOR_IMPLEMENTATION.md),
[протокол](PROTOCOL.md), [аппаратный эксперимент](evidence/native-write-roundtrip.json).

## B. Помощник без изменения прошивки

| Возможность | Как получить | Что уже есть / что добавить |
|---|---|---|
| Громкость, сочетания, текст, короткие последовательности | Исполнитель ОС по action ID | Windows worker есть; физическая приёмка жестов открыта |
| Запуск выбранной программы/процесса | Отдельное действие с программой, аргументами и рабочим каталогом | Сейчас фиксированные Word/Notepad/Calculator; произвольный процесс ещё не реализован |
| Работа при закрытом редакторе | Rust runtime владеет событиями, окно только редактирует и наблюдает | **Пока отсутствует:** watchdog прекращает монитор/правила без UI polling; tray и автозапуска нет |
| Обычные нажатия, удержания, сочетания | Цифровой InputSource с привязкой к устройству | Глобального источника ещё нет; добавить отдельно от FB |
| Условия по глубине | Уже существующий FB-поток | Поток получен по двум адресам; карта, полный ход и устойчивость должны быть проверены |
| Double tap, контекст приложения, программные слои | Чистые автоматы и состояние приложения | Глубина/удержание группы уже есть; остальные автоматы и контекст запланированы |
| Программные макросы и скрипты | Каталог действий и отдельный контролируемый исполнитель | Простые последовательности есть; скрипты и расширения запланированы |
| LLM, почта, Telegram, цепочки действий | Провайдеры событий/действий ОС и сервисов | Запланировано; сетевые интеграции не встроены в firmware |
| Музыка/уведомление цветом клавиши T | Приложение вычисляет кадры, stock 32 временно выводит RGB | Временная RAM-запись и таймер найдены в HEX; время, возврат и физический вывод не приняты |
| Уведомление на полосе | Нужен доступ к отдельной поверхности | Через исследованный штатный API не доступно; см. C |

Для цифровых правил возможны два маршрута: наблюдать обычный ввод IO либо назначить
штатными средствами редкий HID-код и использовать его как триггер. Маршрут
Main/Fn/DKS/макрос → F13…F24 → помощник требует проверки конкретного назначения.
Такой код не гарантированно свободен в других приложениях. Цифровой ввод после
remap не равен физическому адресу клавиши; Fn может вообще не выходить в ОС.

Raw Input позволяет различать источники и получать ввод в фоне. Он не является
обещанием глобального подавления ввода других приложений.
[Документация Microsoft](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input).
Поэтому жест, запускающий действие компьютера, по умолчанию может сопровождаться
обычным вводом исходных клавиш. Полная замена исходного действия — отдельная
возможность, которую UI не должен подразумевать.

Работа программы, скрипта или интеграции не требует изменения firmware сама по
себе. От устройства нужен доступный триггер. План доведения существующего worker
до фонового помощника: [модуль companion](../modules/companion.md).

## C. Где оправдано расширение firmware

| Требование | Почему штатного пути недостаточно сейчас | Предлагаемое расширение / граница |
|---|---|---|
| Произвольные кадры полосы от ОС | Прямой setter не найден; key RGB 32 полосу не адресует | Малый API CAPS/FRAME/RELEASE поверх существующего encoder; прототип, ещё не установлен |
| Явное временное владение светом и предсказуемый возврат | У stock 32 есть внутренний таймер, но не проверенный контракт release/TTL | Версионированный контракт поверхностей; сначала полоса, клавиши — отдельная оценка |
| Свои анимации без фонового процесса | Формат загрузки произвольной автономной анимации не подтверждён | Renderer/таблицы в firmware после проверки RAM/flash и бюджета исполнения |
| Жесты/слои сверх штатных режимов, работающие на любом ПК без помощника | Host runtime существует только в своей ОС; штатные форматы имеют конечную семантику | Дополнительные автоматы и таблицы устройства; объём и реализуемость ещё исследовать |
| Условно заменить исходный ввод до его отправки в ОС | Наблюдение на компьютере не отменяет уже переданный HID-ввод | Вмешательство в обработку устройства; ядровой фильтр ОС — иной, более глубокий путь, вне первой версии |
| Более удобные события датчиков и идентификаторы действий | Штатный FB ещё требует приёмки и не является обещанием полного event API | Дополнительный поток при доказанной необходимости; не начинать переписывание ADC/RT с нуля |

Перепрошивка **не гарантирует** неограниченное число слоёв, макросов или событий.
Увеличение ёмкости сначала проверяется на действующей firmware. Стабильное поведение
сложных правил на ПК часто дешевле получить улучшением помощника. Firmware нужна,
когда упираемся в доступ к железу, автономность либо обработку до обычного HID-вывода.

Для полосы есть воспроизводимый результат: десять позиций можно заменить в готовом
выходном кадре, сохранив RGB клавиш и текущий штатный эффект. Изолированный Rust API
и оригинальный ARM encoder проверены программно. Это не аппаратная приёмка и не
готовая прошивка. [Контракт](firmware/panel-host-api.md),
[прототип](../experiments/panel-api/README.md), [перенос](firmware/ROADMAP.md).
Запись firmware владельцем не разрешена; индивидуальные данные и recovery ещё
не подготовлены. Исследование C не блокирует выпуск A и B.

## Как это выглядит для пользователя

По умолчанию открывается обычный редактор клавиатуры. Помощник включается отдельно,
автозапуск при входе в ОС — отдельная настройка. Прошивка не предлагается как
необходимое условие подключения или настройки макроса.

У назначения показывается короткое место исполнения: **«Клавиатура»** или
**«На компьютере»**. Если функции нужен дополнительный API, рядом с ней —
**«Требует расширения устройства»** с объяснением. Подробности доступны по запросу,
без трёх копий редакторов и выбора технического «уровня» для каждой операции.

| Пример | Предпочтительный путь | Что показывать |
|---|---|---|
| F12 выполняет короткий аппаратный макрос | A, запись в устройство | Использованная память; работа без помощника после аппаратной приёмки |
| Удержание A+S запускает выбранную программу | B, помощник | Требование фоновой работы; исходный ввод сохраняется |
| Глубокий PgUp повышает громкость | B с проверенным FB; stock DKS→маркер как отдельный кандидат | Порог и действие; сейчас физическая приёмка не завершена. Media в byte-код DKS не помещать без доказательства формата |
| T мигает при уведомлении | B, если принят stock RGB 32 | Зависимость от приложения и доступность поверхности; локальный preview отдельно |
| Полоса показывает непрочитанную почту | C + B | Расширение даёт вывод, помощник получает почту и рассчитывает сцену |
| Дополнительный автономный слой | Сначала возможности A, затем исследование C | Отличие от программного слоя и факт сохранения на устройстве |

Нельзя незаметно переносить аппаратное действие в фон при нехватке памяти.
Редактор предлагает вариант и показывает изменение зависимости. Остановка
помощника не сбрасывает сохранённые параметры клавиатуры. На другой ОС профиль
сохраняет свои варианты команд; неподдержанный вариант отмечается, а не выполняется
командой Windows. Скрипты, сети и сторонние процессы не запускаются от импорта.
