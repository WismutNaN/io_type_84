# Исследование IO Type 84 Magnetic

Дата: 2026-09-13. Цель — проверить фактическое подключение и установить основание для самостоятельного конфигуратора.

## Результат

**Native HID-подключение работает.** Оба служебных интерфейса открылись через hidapi без установки собственного системного драйвера. На интерфейсе `FF68:0061` получены корректные ответы на запросы информации и настроек. HID-сеансы закрыты после проверки; команды изменения настроек, калибровки, сброса, тестового режима и обновления прошивки не отправлялись.

| Manufacturer string | IO |
| USB VID/PID | `0C45:80D6` / `3141:32982` |

## HID-интерфейсы

| Интерфейс | Usage page / usage | Дескриптор и роль |
|---|---|---|
| MI_00 | `0001:0006` | Обычная клавиатура |
| MI_01 | Consumer Control, System Control, Keyboard, Mouse | Несколько стандартных коллекций |
| MI_02 | `FF68:0061` | Input 64 байта, Output 64 байта; подтверждённый обмен настройками |
| MI_03 | `FF67:0061` | Output 4096 байт, Feature 64 байта; открыт, обмен данными не проверялся |

Report ID в двух служебных дескрипторах отсутствует: используется нулевой ID. На Windows hidapi при записи требует отдельный начальный байт ID; это 65 байт буфера для 64 байт содержимого MI_02. Этот байт не является заголовком протокола.

## Что прочитано

В последовательном снимке проверены 80 пар запрос/ответ: длина ответа 64, заголовок `55`, команда, адрес и размер блока. Повторов по тайм-ауту не потребовалось. Это проверка доступности чтения, а не испытание устойчивости или скорости.

| Блок | Команда | Размер | Уровень подтверждения |
|---|---|---:|---|
| Информация | `10` | 48 | Прочитана и частично декодирована |
| Общие настройки | `11` | 56 | Прочитаны |
| Основные назначения | `12` | 512 | Прочитаны все 128 записей по 4 байта |
| Fn-назначения | `16` | 512 | Прочитаны |
| Эффект подсветки | `13` | 16 | Прочитан |
| Пользовательские цвета | `14` | 512 | Прочитаны |
| RT / ход | `17` | 1024 | Прочитаны 128 записей по 8 байт |
| DKS | `18` | 1024 | Прочитана таблица, в снимке нулевая |
| Каталог макросов | `15` | 400 | Прочитан каталог; тела макросов не исследованы |
| Статус A/S/D | `68` | 24 | Ответ получен; валидные измерения не подтверждены |

Ответ `68` содержит первые байты записей `31`, `32`, `33`, совпадающие с переданными идентификаторами A/S/D, остальные байты нулевые. Это может быть эхо или результат запроса без необходимого режима. Не считать такой ответ доказательством телеметрии. Нужен отдельный эксперимент с изменением физического хода, контролем режима и единиц измерения.

Сохранены [информация устройства](evidence/device-info.json), [снимок обмена](evidence/read-snapshot.json), [дескрипторы](evidence/hid-descriptors.json). Время отдельных блоков имеет грубую точность и не используется как оценка задержки приложения.

## Почему AureTrix не является готовым драйвером IO

Локальный AureTrix: commit `bdcfca2f30df45ec4348c2d52f1aca52a7e594fc`. `src/services/KeyboardService.ts` создаёт SparkLink SDK с `usagePage: 65440` (`FFA0`), `usage: 1`. Фактическое IO-устройство предоставляет `FF68/FF67`, usage `0061`; в коде сайта используется другой формат обмена. Это опровергает практическое предположение, что достаточно подставить VID/PID в текущий AureTrix. Не исключается неизвестное родство платформ, но оснований использовать SparkLink здесь нет.

В AureTrix есть полезные примеры Vue-интерфейса, геометрии, выделения клавиш и редакторов. Его DKS, SOCD, MT, MPT, TGL и END — страницы-заглушки. Нельзя принимать наличие страницы или API SDK за поддержку функции на IO.

Файл LICENSE AureTrix содержит MIT, а package.json — поле ISC; при переносе кода сохранить происхождение и уведомления и проверить метаданные. HallJoy содержит GPLv3 и отдельные условия коммерческого распространения; код оттуда пока не переносить. Он не требуется для найденного IO-протокола. Юридическая совместимость будущего набора зависимостей отдельно не исследовалась.

В скопированном `node_modules` AureTrix обнаружены junction-ссылки на `G:\APPS\AureTrix_driver\...`. Их нельзя считать переносимым окружением: при необходимости запускать референс следует восстановить зависимости из lockfile.

## Что обнаружено на официальном сайте

HTML с [advanced-keys](https://web.io.vision/advanced-keys) и опубликованные JS-файлы прочитаны как данные. Код сайта не исполнялся для подключения. Найдено точное описание `IO Type 84 Magnetic White`, выбранное по VID/PID и product string, и обработчик `config/protocols/default`.

Для White описано 84 физических клавиши с разреженными адресами в диапазоне 0…108. Блоки протокола содержат 128 позиций; порядковый номер клавиши на экране не является её адресом. Например: A=49, S=50, D=51, Fn=85, Backspace=92, Home=104.

Конфигурация модели показывает:

- Основные и Fn-назначения; F1…F12 ограничены для изменения во Fn-редакторе сайта.
- Ход 0,1…3,2 мм, шаг UI 0,01 мм; быстрый сброс/срабатывание и мёртвые зоны. Значение по умолчанию UI не заменяет прочитанное значение устройства.
- Продвинутые режимы RS, SOCD, DKS, MT, TGL.
- Частоты в UI: 1000, 4000, 8000 Гц; соответствие кодов частот ещё требуется явно проверить.
- Калибровка и режим стабильности; освещение и макросы.

Это описание возможностей интерфейса сайта. Запись и исполнение каждой функции на данном экземпляре требуют проверки. Общий bundle содержит функции для экранов, других моделей и анимаций, которые могут быть недоступны IO White.

## Критический разбор исходной идеи

Стек подходит, а разделение на конфигуратор и помощник отражает разные условия работы. DDD полезен для разграничения аппаратной конфигурации, правил, подсветки и действий ОС; начать следует с модульного монолита.

«Сила нажатия» в продукте уточняется как **глубина хода**. Доказанного датчика усилия и преобразования в ньютоны здесь нет. Сложные условия по глубине возможны в помощнике только при проверенной телеметрии; иначе доступны поддержанные режимы прошивки и цифровые события.

Количество программных слоёв и локальных профилей может быть произвольным в пределах ресурсов приложения. Количество аппаратных слоёв, профилей, DKS и макросов ограничено протоколом/прошивкой. Не обещать четыре слоя из AureTrix: на IO пока прочитаны только основная и Fn-таблицы.

Фоновая обработка не получает задержку 0,125 мс только потому, что сайт предлагает USB 8000 Гц. Измеряется весь путь события до действия, а объём RGB-трафика учитывается отдельно.

2. Восстановить семантику ключевых полей; сохранять неизвестные байты.
3. Сделать конкретный diff одного назначения, применить, прочитать обратно, проверить физически и восстановить исходное значение.
4. Проверить сохранение после переподключения отдельно от подтверждения записи.
5. Проверить живой ход и временный RGB-поток; при отрицательном результате оставить функции недоступными с объяснением.
