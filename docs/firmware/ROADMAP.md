# Продолжение: готовая основа и проверка отличий IO

Порядок принят 2026-09-14. Это **необязательная ветка C** из [карты интеграции](../INTEGRATION.md).
Основной продукт сначала раскрывает штатные настройки и фоновый помощник без новой
firmware. Здесь готовится расширение для конкретных ограничений железа и автономной
логики. Прошивать пользовательскую клавиатуру не разрешено; готовность C не блокирует A/B.

По objects.md дополнительно оценивается [input/output bridge](../objects/FIRMWARE_CONTRACT.md),
если stock + OS adapter не обеспечат захват/выходные leases. Это не часть готового
API полосы и не повод переносить весь host engine в MCU. Сначала
[gates G1/G2](../objects/COMPATIBILITY.md), затем конкретный offline port/recovery.

Оценка новых сценариев: [MCU и реализуемость](chip-feasibility.md),
[hardware/software cases](case-coverage.md). Получен полный Sonix manual v1.7:
до размещения вставки нужно учесть [CS/SM/BOOT и остановку CPU при flash](sonix-manual-safety.md).
Владелец сообщил, что на его обращение производитель отказал в предоставлении данных;
[материалы запроса](manufacturer-request.md) остаются историей. Источники IO больше
не ожидаются как следующий результат. Приоритет продукта —
[полная матрица и этапы N1–N7](../FEATURE_MATRIX.md), [ADR-0008](../adr/0008-stock-first-delivery.md).
Шаги ниже — условия продолжения C для конкретного недоступного сценария, не очередь
перед выпуском конфигуратора и фона.

## 1. Повторно использовать результаты — выполнено

- OpenAula выбран как ближайший референс overlay, жестов и собственного RGB renderer.
- Получен официальный Sonix DFP с описанием MCU и инструментами статического анализа.
- Статья связана с конкретной ревизией исходников, её аппаратные неточности отмечены.
- Созданы атлас IO, карта калибровки и схема штатного ISP с воспроизводимыми проверками.

Не повторять поиск ADC/RT/ISP с нуля. Для новой задачи сначала смотреть
[карту применимости OpenAula](../reference-projects/OPENAULA.md), затем соответствующий
SDK-файл и только после этого неизвестную часть IO.

## 2. Offline port plan — частично выполнено

Подготовить IO-specific описание точек расширения, без изменённого flash-образа:

Для полосы уже найдены две call sites и их исходные байты; в оригинальном ARM
encoder проверена подмена только её выходного участка и восстановление stock-кадра.
Восстановлена начальная RAM с USB callbacks. [Контракт](panel-host-api.md) и
[Rust-прототип](../../experiments/panel-api/README.md) проверяют CAPS/FRAME/RELEASE,
владение и TTL. Свободная RAM/flash и ABI обёрток ещё не выбраны; перечень ниже
остаётся проверкой переноса, а не списком выполненных работ.

| Переиспользуемая часть | Что проверить для IO | Критерий готовности |
|---|---|---|
| Patcher с hash/byte guards | Точный образ, оригинальные инструкции, допустимые интервалы | План показывает каждый изменяемый байт и отказывает на другой ревизии |
| Hook обычного действия | Сигнатура/регистры/стек, прохождение key-up и модификаторов | Проверенный assembly trace входа/выхода, тест последовательностей без зависших клавиш |
| Периодический callback | Порядок HE, HID и вывода света; время выполнения | Определена точка вызова и бюджет задержки |
| Состояния жестов | Таймер, rollover, отпускание, reset/suspend | Чистая модель исполняется в host-тестах с граничными последовательностями |
| RGB renderer | Карта клавиш, planes, brightness, compositor полосы | Отдельные адаптеры 84 клавиш и десяти позиций; preview на тех же входах |
| RAM/flash вставки | Все обращения, стек, DMA, динамические настройки | Подтверждённые интервалы без пересечений; нули HEX сами по себе недостаточны |

Сначала использовать штатные HE/RT/USB routines. Имена функций в нашем атласе —
ориентиры, не готовый ABI. Конкретный IO hook и свободная область пока не приняты.
Проверить совместимость соглашений вызова и FPU даже если вставка собрана без float.

## 3. Подготовить восстановление конкретной платы

Общая документация MCU получена; не закрыты точный part/PCB, USB ISP Boot IO,
RDP/BOOTPINEN и физический доступ. При CS1/CS3 нельзя получать backup через unlock:
CS1→CS0 уничтожает User, CS3→CS0 ещё и Boot. Комплект OEM не предоставлен;
восстановление нужно обосновать своими измерениями и документацией на подходящем
стенде. OpenAula/DFP/manual и HEX не заменяют backup конкретной платы.

Нужны маркировка MCU, ревизия PCB и фотографии/схема дорожек BOOT/SWD, затем
документация о Code Option, security и служебных областях. USB-дескрипторы следует
сначала читать в обычном режиме. Не отправлять ISP magic просто ради перечисления.

Разобрать возможное чтение flash и калибровки с явным allowlist; автоматический
unlock/erase исключён. Сохранить индивидуальные данные с покрытием диапазонов и
двумя совпадающими чтениями там, где чтение доступно. Если защита не позволяет
получить backup, зафиксировать это как ограничение и работать с запасной платой.
Отдельно доказать recovery на той же аппаратной ревизии, как описано в
[update-recovery](update-recovery.md).

Без физической идентификации и пути восстановления результат пункта 2 останется
проверяемым проектом переноса. Наличие похожей AULA не снимает этот барьер.

## 4. Будущие возможности

| Пользовательская идея | Где выполнять | Что требуется от firmware |
|---|---|---|
| T мигает при Telegram, полоса показывает почту | Источник уведомлений и правила на компьютере | Временный кадр/сцена и надёжный возврат к штатному свету |
| Музыкальная подсветка | Анализ аудио на компьютере | Канал временных кадров либо компактных параметров сцены; ограничение частоты |
| Свои автономные анимации | Renderer в клавиатуре | Проверенная вставка, таймер и доступ к кадровым буферам/полосе |
| Дополнительные слои, tap/hold/chord | На первом этапе host; автономно — overlay | Штатные состояния HE, корректные key-up, ограниченные таблицы и память |
| Запуск Word, скрипт, LLM, почта | Каталог действий и платформенный runtime компьютера | Событие/идентификатор действия, а не код интеграции с сервисом |

Все пункты — проект расширения, не готовые capabilities. Для части RGB клавиш
может хватить штатной команды `32`, но ещё нужно доказать её обратимость.
У IO-полосы прямой host setter пока не найден. OpenAula показывает способ добавить
renderer, но не решает сам по себе доставку уведомлений из ОС.

UI не должен раскрывать адреса, ABI или режимы программатора в обычной настройке.
Пользователь выбирает действие, условие и световую поверхность. Место исполнения
и зависимость от приложения показываются только там, где влияют на поведение.
Расширения firmware и recovery остаются отдельным исследовательским инструментом
до аппаратной приёмки и определения модели совместимости.
