# Штатная обработка ввода White 1.17

Проверено 2026-09-14. Задача: выяснить, может ли штатная клавиатура убрать исходный
PgUp и предоставить помощнику данные для выбора действия. Исходный HEX закреплён
по SHA-256; изменённая прошивка не создавалась, ISP/калибровка/reset не запускались.

## Результат

**Штатная прошивка имеет больше полезных примитивов, чем отражал наш редактор.**
Есть ветка назначения без выдачи исходной клавиши, внутренние коды мультимедиа,
поддержка модификаторов в DKS и штатный выбор tap/hold. Перепрошивка для этих
примитивов не нужна. Полный надёжный захват для помощника ещё не принят:
аналоговый ход при отключённом назначении получен на устройстве, а цифровой
отрицательный контроль в этой сессии остался незавершённым.

| Возможность | Что установлено | Граница результата |
|---|---|---|
| Убрать исходное действие | `[5,0,0,0]` обнуляет код перед общим обработчиком; ARM-исполнение не выдаёт исходный PgUp | На USB записано и прочитано обратно; физическое отсутствие исходного события требует синхронного положительного/отрицательного контроля |
| «Пустое» назначение | `[0,0,0,0]` возвращает заводской код; `[2,0,0,0]` для PgUp тоже выдаёт PgUp | Прежняя кнопка «Отключить» была ошибочной, удалена до приёмки настоящего маршрута |
| Маркеры для помощника | `[2,0,0x68,0]` вместо PgUp выдаёт F13 в ARM-проверке | Маркер не является эксклюзивным каналом: он виден ОС/другим приложениям. F13–F24 добавлены в выбор назначения |
| Глубина без обычного действия | При `[5,0,0,0]` + simulation обе физические клавиши дали 0–3980 мкм и возвраты к нулю | Не измерены потери, порядок одновременных клавиш, восстановление потока, задержка и длительная работа |
| Simulation `66/67` | Включает/выключает флаг `0x2000036D`; сам по себе не отменяет обычное назначение | Это источник телеметрии, не готовый capture lease |
| DKS → громкость | Внутренние `B9/BA` превращаются в Consumer `00E9/00EA`; работает общий путь DKS | Исполнены исходные ARM-функции и проверены буферы отчётов; физический DKS-тест ещё нужен |
| DKS + модификаторы | Чётные offsets 4/6/8/10 — маски модификаторов, а не резерв | Проверено сочетание Shift+PgUp; DTO пока сохраняет эти raw-байты, отдельного редактора масок нет |
| Выбор лёгкого/глубокого | DKS может отпустить первое действие при глубоком ходе, но уже выданное нажатие остаётся | Перенос PgUp на последнюю фазу не отменяет его после глубокого нажатия |
| MT | `[9,B9,4B,14]`: короткое нажатие выбирает PgUp, превышение таймера — громкость | ARM-тест подтвердил разные ветви. Это выбор по времени, не по глубине; проверены тики, не реальная задержка USB |
| Макрос в памяти | Wire kind `3` исполняет клавиатуру, `1` кнопки мыши | Исправлен наш codec. Запись/чтение тела не заменяет проверку аппаратного воспроизведения |
| Windows/Mac | Режим Mac меняет Win/Alt после чтения таблицы; Fn+M в текущем Fn-слое вызывает FUNC 9 | Режим хранится отдельно от девяти блоков RawSnapshot; его нельзя считать восстановленным по их хешу |

## Как проверялось

[Стенд](../../tools/verify_stock_input.py) исполняет **исходные ARM-инструкции**, а не
переписанную модель DKS. Использованы существующие loader/Unicorn из исследования
OpenAula/IO. В эмуляции доступны только ROM и SRAM; обращения к периферии не
отображены, исполнение flash/boot primitives и запись вне SRAM завершают проверку.
Конфигурации подставляются только в память эмулятора, файлы firmware не меняются.

Основные адреса:

- `0x43FC` — обработка готового хода и DKS (в старом атласе ошибочно объединена с ADC).
- `0x4FC8` — диспетчер назначения; `0x51AE` — его switch, не отдельная функция.
- `0x112A8` — подготовка клавиатурных/Consumer/system отчётов; таблица Consumer `0x13BE0`.
- `0x11BC/0x11F8` — нажатие/отпускание пары modifier-mask + action-code.
- `0x1230` — отпускание DKS tap; `0x42F4/0x4348/0x4394` — MT/таймер/очередь отпусканий.
- `0x3310` — исполнение шага макроса; `0x5C30` — в том числе замена Win/Alt.

Проверены обычное назначение, пустые варианты, F13, no-output, шесть media aliases,
три схемы DKS на лёгком/глубоком цикле, MT до/после таймера, оба типа макросов,
simulation и Windows/Mac. Перебраны **81** допустимая комбинация off/tap/hold
одного действия на четырёх фазах DKS при порогах `[16,30,29,16]`.
Не найден вариант, который выдаёт PgUp на лёгком цикле и ни разу на глубоком.
Это ограниченный перебор, а не доказательство для всех возможных порогов/аномалий.
Статический разбор подтверждает безусловный tap последней фазы после достижения первой.

USB-передача не эмулируется. Завершение обработки отчёта моделируется сбросом dirty
flags перед исполнением штатных очередей отпускания. `emissionRequests` — обращения
к общему обработчику: повторные обращения MT не следует считать отдельными HID down.
[Результат и проверенные инварианты](../evidence/stock-input-emulation-v1.17.json).

## Аппаратная сессия и её ограничения

Были сохранены девять исходных блоков и подготовлен diff только для base-назначений
слотов 105/108. После SET/readback был включён штатный simulation. Получено 9731
отсчёт PgUp и 11003 PgDn, максимум 3980 мкм для каждой, включая последующие нули.
Затем simulation остановлен, исходный base восстановлен; SHA всех девяти блоков совпал.
[Сводка](../evidence/stock-input-hardware-v1.17.json).

Изначальный профиль уже назначал этим клавишам громкость. Первый наблюдатель
считал только PgUp/PgDn/F13/F14, поэтому цифровой baseline был пустым и отрицательный
результат нельзя принять. Добавлены Consumer reports и проверка положительного
контроля; следующие попытки остановились **до SET**, поскольку контроля не получили.
Владелец сообщил, что время второй проверки было непонятно. Больше автоматических
переходов между аппаратными фазами не допускаем: стенд требует интерактивный терминал
и Enter перед изменением/измерением/восстановлением. Обновлённая процедура пока не
пройдена на железе. Постоянные последовательности нажатий не сохраняются.

После сессии владелец обнаружил перестановку Win/Alt; переподключение USB не помогло.
Проверка Raw Input показала нажатия и отпускания модификаторов. Все девять блоков
конфигурации оставались прежними. Штатный Fn+M вернул кнопки и переключение языка
в норму, что владелец подтвердил. Он допускает случайное нажатие Fn+M.
Причинная связь перестановки с тестовой записью не установлена.

Это выявило отдельный пробел: OS-mode сохраняется через `0x54C4` в блоке `0x8200`
(байт `0x820D` загружается в `0x200000A8`). Текущий RawSnapshot этот блок не читает.
**Совпадение хешей девяти блоков не означает полный backup всех настроек устройства.**
Не добавлять произвольное чтение flash или сохранение этого блока без штатного API.

## Что меняется в приложении

- Исправлена граница типов макроса: доменный/profile `kind=1` остаётся клавиатурой,
  `3` мышью; wire теперь кодирует их как `3` и `1`. Старые локальные профили сохраняют
  намерение; уже записанные ошибочные тела читаются согласно их реальному исполнению.
  Автоматическая перезапись сохранённых макросов не выполняется.
- Исправлена проверка DKS: action индекс и phase индекс больше не смешиваются.
  Теперь действие 1 можно назначить последней фазе, а ссылку на отсутствующее действие
  корректно отклонить. Это не превращает фазу отпускания в exclusive depth.
- DKS/MT/TGL получили выбор Vol+/Vol−/Mute/PlayPause/Next/Previous; F13–F24 доступны
  в каталоге кодов. Глобальные capabilities не повышены по одному ARM-тесту.
- Удалена ложная команда отключения `[2,0,0,0]`; её отображение теперь соответствует
  заводскому действию. `[5,0,0,0]` остаётся кандидатом диагностического стенда.

## Следующий результат

Сначала синхронно принять два маршрута на stock: no-output + FB и DKS → F13/F14.
Для каждого нужны положительный цифровой контроль, отсутствие исходного действия,
полный цикл/отпускание, одновременные клавиши и восстановление исходного поведения.
Стандартные настройки Fn и OS-mode учитывать отдельно. Запись разрешать только между
циклами нажатия, когда пользователь отпустил клавиши.

Если маршрут проходит, помощник получает целый жест и выбирает одно действие;
профиль должен явно показывать зависимость от фонового процесса и иметь путь выхода
при его аварии. Постоянный no-output сам по себе не возвращает клавиши при завершении
помощника — это ещё не надёжная передача владения. Firmware-extension для capture
пока **не обосновано как необходимое**. Для автономных произвольных условий, полосы,
аналогового gamepad и общих выходных lease остаются отдельные проверки.

Источники: закреплённый [HEX IO](https://web.io.vision/IO_Type_84_Magnetic_White_V1.17.hex),
локальный bundle сайта (SDK DKS/macros), [OpenAula](../reference-projects/OPENAULA.md),
[Raw Input registration](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerrawinputdevices)
и [GetRawInputData](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getrawinputdata).


## Аппаратная приёмка захвата, 2026-09-14

[Полные ограниченные счётчики](../evidence/stock-capture-acceptance-v1.17.json).
Проверен `[5,0,0,0]` одновременно в base/Fn только слотов 105 и 108.
До записи и после восстановления Raw Input зарегистрировал по два down/up
Volume Up и Volume Down. Во время отрицательного контроля обе команды и PgUp/PgDn
отсутствовали; пробел дал шесть сообщений IO и подтвердил работу наблюдателя.
Одновременно FB дал 2465/1102 пакета, пики 3,97/3,96 мм. По инструкции владелец
нажимал также Fn+PgUp/PgDn; FB не передаёт отдельного бита текущего Fn.

В более раннем base-only прогоне получены 7655/5874 пакета, пики 3,98/3,96 мм
и возвраты к нулю. Последующий прогон дал минимум 0,13/0,12 мм; его счётчик
возвратов ниже 0,10 мм остался нулевым. Это не означает зажатую клавишу:
порог возврата будущего helper — 0,20 мм; долговременная устойчивость отдельно.

Все девять блоков после восстановления совпали с исходной ревизией
`562dce79deddc0a2f14da00f04b0251901fc74ddac80f8d653bf1d786caab9b5`.
Владелец подтвердил обычную работу. Захват двух клавиш на stock принят для первого
host-сценария. Это уточняет прежний незавершённый цифровой контроль выше;
не является приёмкой всей модели objects.md, recovery после аварии или новой firmware.
