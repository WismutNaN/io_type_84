# MCU и карта памяти White 1.17

Основание: [официальный PDSC Sonix](https://liveupdate.sonix.com.tw/sonix/develop_tool/MCU/DFP/SONiX.SN34F2_DFP.pdsc),
[DFP 2.0.4](https://liveupdate.sonix.com.tw/sonix/develop_tool/MCU/DFP/SONiX.SN34F2_DFP.2.0.4.pack)
и [точный HEX IO](https://web.io.vision/IO_Type_84_Magnetic_White_V1.17.hex).
Хеши — в [манифесте](../evidence/firmware-research-sources.json).

## Идентификация

DFP описывает SN34F280 как Cortex-M4 с FPU, до 192 МГц, USER ROM 504 КиБ, SRAM 160 КиБ.
В семейство входят разные корпуса/варианты; маркировка именно IO пока неизвестна.
PDSC, `SN34F280.h`, `SN34F280.svd` и `startup_SN34F280.s` дают согласованный
источник для регистров и IRQ. Это значительно сильнее оценки MCU по VID/PID или
первому stack pointer. Пакет найден напрямую на сервере Sonix; отсутствие семейства
в рассмотренном центральном списке Keil не означает отсутствия документации.

Совпадения в IO проверены независимо от OpenAula:

- Reset entry `0x204` воспроизводит startup: очистка бита `0x10000` в
  `0x4001F004`, запись `0x10000` в `0x4001F000`, переход на entry runtime.
- SDK объясняет найденные адреса SCU, ADC, USBHS, DMA, GPIO и FLASH; IRQ согласуются
  с векторами IO. Наличие числового литерала само по себе ещё не доказывает
  использование каждого периферийного блока.
- По `0x7DFFC` находится `0xAAAA5555`. Startup прямо определяет это значение как
  **ISP_MODE_FLAG для USER MODE**. Это не установленная CRC или цифровая подпись.

## Разные адресные пространства

| Область | Адреса / размер | Доказательство и предел |
|---|---|---|
| Логический USER ROM | `[0, 0x7E000)`, 504 КиБ | Размер штатного ISP payload и FLM |
| Область кода/данных в HEX | `[0, 0x16264)` плюс 4 байта flag | 90 728 реально заданных байт; пропуски не означают свободное место установленного устройства |
| USER_MODE_FLAG | `[0x7DFFC, 0x7E000)` | Последнее слово в startup и HEX |
| SRAM семейства | `[0x20000000, 0x20028000)`, 160 КиБ | PDSC; фактическое использование IO требует карты всех буферов/стеков/DMA |
| Начальный SP IO | `0x20007E48` | Вектор образа; не верх физической RAM |
| Boot ROM entry | Thumb-адрес `0x00200301` | Литерал IO в переходе `0x1D8`; содержимого этой области в HEX нет |
| FMC staging / registers | `0x00600000` / `0x00601000` | Код IO и определение FLASH в SDK |
| Физическое адресование FLM | USER-адрес + `0x2000` | Статический разбор `ProgramPage` официального FLM |

В `SN34F280_504.FLM` `EraseChip` проходит физический диапазон
`[0x2000, 0x80000)` шагом 4 КиБ. Это алгоритм программатора, а не размер
транзакции приложения или ISP. В IO `0x2274` выбирает remap offset `0`/`0x2000`
по состоянию SCU. Нельзя смешивать физический адрес, логический USER ROM и alias
Boot ROM, объявляя «последние 8 КиБ всегда защищённым загрузчиком».
Состояние защиты IO и действие USB ISP на Boot/SM/Code Option ещё не установлены.

Уточнение по полному руководству Sonix v1.7: физическое чтение MM идёт через
`[0x00200000, 0x00280000)`, первые 8 КиБ — Boot, далее User. Boot находится во
flash: переход CS3→CS0 стирает и его. Для CS1→CS0 стирается только User. Это
документированные свойства семейства; состояние защиты IO и соответствие USB ISP
команд внутренним FMC пока неизвестны. [Подробная карта и security](sonix-manual-safety.md).

## Прикладные области IO

| Логический адрес | Назначение | Основание |
|---|---|---|
| `0x8200` | Блок panel/options, формируется 16 байт с маркером `A5` | `0x54C4 → 0x3630` |
| `0x8400` | 128 значений максимального ADC, u16 | Инициализация и завершение калибровки |
| `0x8500` | 128 значений минимального ADC со статусом, u16 | Те же пути |

Это фрагмент карты, а не allowlist для произвольной записи. Пустые/нулевые участки
официального HEX нельзя автоматически использовать под расширения: там могут
лежать установленные настройки, служебные данные либо рабочие области firmware.
Нужны анализ обращений и сравнение с конкретным устройством.

## Официальные ориентиры восстановления

В DFP есть трёхстраничная схема `Documents/SN34F280_STARTKIT_V1.3.pdf`.
На странице 2 визуально проверены: JP11 соединяет P1.3 с GND как Boot loader pin;
JP6 выводит SWDIO P3.5 и SWCLK P3.6. Страница 3 — схема отдельного SN-Link,
его SN32F247 не является основным MCU клавиатуры.

Это схема **оценочной платы Sonix**, не IO. Номера площадок, корпус, уровни питания,
наличие BOOT/SWD и доступность чтения на IO надо устанавливать по его PCB.
Подключение программатора и изменение защиты в этом исследовании не выполнялись.
Получен полный официальный manual SN34F280 v1.7 (569 с.), включая flash/security,
SWD/Writer и Code Option. [Новые сведения и противоречия](sonix-manual-safety.md),
[реальная гибкость MCU](chip-feasibility.md). Отдельной спецификации USB ISP
установленного загрузчика всё ещё нет; общий manual её не заменяет.
