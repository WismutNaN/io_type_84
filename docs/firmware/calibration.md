# Калибровка и магнитная обработка IO

Статический анализ точного White 1.17, 2026-09-14. Значения конкретного устройства
не извлечены. [Машинные свидетельства](../evidence/firmware-safety-v1.17.json),
[воспроизведение](REPRODUCING.md).

## Два разных вида индивидуальных данных

**Калибровка клавиш** связывает ADC магнитных датчиков с ходом. В IO найдены
её таблицы в USER ROM и рабочие копии RAM. Прошивка умеет изменять их.

**Заводские trim/security данные самого MCU** могут относиться к генераторам,
аналоговой части и служебным областям производителя. Их состав и расположение
на установленном MCU пока не установлены. Клавишные таблицы не являются полным
backup таких данных; публичный HEX не доказывает их наличие или сохранность.
Полный manual теперь определяет SM 2 КиБ, уникальный номер и Code Option;
[карта и ограничения](sonix-manual-safety.md). Состав заводских trim и их значения
конкретного IO этим не установлен; SM Page 0/1 не изменять.
Нельзя называть все индивидуальные значения «вшитой заводской калибровкой» без
снимка и выяснения происхождения: часть могла изменяться при эксплуатации.

## Найденные таблицы

| Данные | USER ROM | RAM | Формат |
|---|---|---|---|
| Максимальный ADC | `0x8400` | `0x2000353A` | 128 × u16 LE |
| Минимальный ADC и статус | `0x8500` | `0x2000363A` | 128 × u16 LE, ADC `& 0x7FFF`, статус `& 0x8000` |

Обе таблицы помещаются в один прикладной 512-байтовый блок. В официальном HEX все
max равны **2200**, все min — **1900**. Это общие defaults образа, не измерения
данного экземпляра. Считать 84 физических клавиши, 128 calibration slots и
индексы сканирования одним массивом нельзя.

## Какие действия пишут flash

`0x41CC` читает настройки и таблицы при запуске. `0x3608` обновляет минимальные
значения/флаги в RAM; записи flash внутри этой функции не обнаружено. Сохранение
надо определять по вызывающему пути, а не по названию режима.

Для команды `64` dispatcher включает calibration mode и очищает маску.
Для команды **`65`** путь по `0xDB1A` сначала вызывает **`0x1930`**, затем выключает
режим. `0x1930` обрабатывает 128 слотов: если статус min не установлен, подставляет
defaults 2200/1900, затем вызывает `0x3630` для 256 байт по `0x8400` и для 256 байт
по `0x8500`. Таким образом, **«остановить калибровку» сохраняет таблицы во flash**.
Сценарий «включить и сразу выключить для проверки» не является чтением.

В reset-ветке с младшим nibble команды `F` и `request[2] = 5` найдены сброс таблиц
к defaults и сохранение. Это не классификация всех reset-команд; иные варианты
нельзя считать безопасными по отсутствию их в этом разборе.

Writer `0x3630` собирает read-modify-write страниц: копирование, стирание, запись.
Функция `0x372C`, похожая на проверку диапазона, фактически возвращает успех.
Нельзя полагаться на неё как на аппаратную защиту. Двойная запись таблиц в одну
страницу также не даёт атомарности при отключении питания.

## Что можно получить из FB

Serializer `0xBF0` формирует сообщение:

| Байты | Значение |
|---|---|
| 0…1 | `55 FB` |
| 2 | key value / адрес события |
| 3 | Статус из старшего бита min |
| 4…5 | Максимальный ADC, LE |
| 6…7 | Минимальный ADC со статусным битом, LE |
| 8…9 | Текущий ADC, LE |
| 10…11 | Рассчитанный ход, LE |
| 12…13 | Дополнительное поле; смысл не зафиксирован |

Текущий monitor использует ADC/ход, но не сохраняет индивидуальные max/min как
backup. Следующий полезный шаг — отдельный инспектор этих полей с provenance и
покрытием адресов. До проверки соответствия физических клавиш и всех слотов такой
набор будет **частичной наблюдаемой копией**, а не полной калибровкой: в покоящихся
ветках есть особенности адресации событий. Непришедшие слоты нельзя дополнять нулями.

## Как получается ход

В `0x6C14` найден float-фильтр с шестью рабочими значениями, соответствующий форме
IIR из исследования [OpenAula HE](https://github.com/cvanelteren/OpenAula/blob/fc3a9200bffd62ac91ca3bf5b3aac56a906a530a/docs/HE_ALGORITHM.md).
Затем обработка `0x3AA8` использует калибровочные пределы, таблицу преобразования
датчика и состояния RT. Найдены нижнее ограничение ADC 1000, индекс сканирования
и таблица отображения по `0x13A90`. Это не линейное деление ADC на константу.

Для UI показываем измеряемый/рассчитанный **ход**, а не силу в ньютонах. Для новых
жестов сначала проверяем полный ход, отпускание и шум на IO. На первом этапе
расширения OpenAula-подобный код должен потреблять штатный результат HE, сохраняя
его фильтр, калибровку и RT. Переписывать аналоговый тракт до такой проверки нет
оснований.
