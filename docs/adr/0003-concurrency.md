# ADR-0003: конкурентность и жизненный цикл

**Дата:** 2026-09-13. **Статус:** HID worker принят и реализован 2026-09-14; tray/runtime ещё не реализованы.

Уточнён [ADR-0007](0007-integration-levels.md): фон — выбор пользователя на штатной
firmware. План отделения UI heartbeat, владения источниками и хранения применённого
профиля — [companion](../../modules/companion.md). Не удалять watchdog без замены
проверками свежести/состояния runtime.

## Реализованная ступень

`KeyboardService` владеет bounded sync queue на 16 операций, один поток владеет HID; async Tauri вызывает его через spawn_blocking. FB агрегируется под коротким Mutex, UI polling 60 мс, watchdog 5 с, дренирование до 64 пакетов за итерацию. Пауза очищает свежие позиции и состояние down, история остаётся до очистки/нового подключения. Закрытие окна останавливает поток; фонового tray пока нет. Нет раннего timeout ответа IPC при продолжающемся apply. Обычная остановка не отменяет уже отправленный SET.

## Контекст

HID-чтение блокируется, протокол не содержит установленного transaction ID, настройки и будущий RGB-поток могут конфликтовать. Помощник должен работать при закрытом окне редактора.

## Рассматриваемые варианты

1. Независимые обращения из UI/сервисов — просто начать, легко перепутать ответы и владельцев.
2. Один worker на физическое устройство и отдельный runtime правил — сериализованный обмен и управляемый поток событий.

## Решение

HID handle принадлежит выделенному worker; одна операция в полёте, bounded queue, команды остановки/отключения обслуживаются без ожидания устаревших кадров. RGB-кадры могут замещаться последним, переходы нажатий не теряются молча. После тайм-аута сеанс восстанавливается перед новыми операциями.

Сначала один Tauri-процесс с tray и Rust-runtime. Raw Input имеет собственную обработку сообщений Windows; callbacks только нормализуют/ставят события в очередь. Прикладная async-координация может использовать Tokio, но доменные функции от него не зависят. Отдельный процесс понадобится для недоверенных расширений, не для каждой подсистемы.

## Последствия

Проще отмена, диагностика и воспроизведение ошибок. Сложнее политика очередей и shutdown. Путь к отдельному пользовательскому агенту остаётся через существующие порты; Windows service пока не требуется.
