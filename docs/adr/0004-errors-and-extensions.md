# ADR-0004: ошибки и расширения

**Дата:** 2026-09-13. **Статус:** предложено; технология worker выбирается отдельным решением перед реализацией.

## Контекст

Ошибки транспорта, недоступная функция и неверный профиль требуют разных действий. Будущие скрипты не должны блокировать обработку клавиатуры или получать неограниченные права через UI.

## Рассматриваемые варианты

1. Универсальная строковая ошибка и выполнение скриптов в UI — мало начального кода, нет надёжного управления отказами.
2. Типизированные ошибки и каталог действий с отдельным исполнителем — больше контрактов, предсказуемое восстановление.

## Решение

Разделить ValidationError, UnsupportedCapability, DeviceDisconnected, Timeout, ProtocolMismatch, ReadbackMismatch, StorageFailure и ActionFailure. Не сводить timeout SET к «ничего не изменилось». IPC возвращает стабильный код и operationId; в диагностике доступны детали.

Встроенные действия имеют схемы и ограниченные параметры. Расширения получают версионированный manifest, явные grants, deadline, cancellation и лимиты. Исполнение вне UI и HID worker. Процесс сам по себе не обеспечивает sandbox: перед подключением чужого кода выбрать и проверить реальную изоляцию. Отказ одного действия не повреждает остальные правила.

Tauri capabilities ограничивают доступ фронтенда; собственные Rust-команды дополнительно проверяют аргументы и доступы. Факт [наличия capabilities](https://v2.tauri.app/security/capabilities/) не заменяет безопасность реализации backend.

## Последствия

Проще показывать конкретную причину и восстанавливать работу. Сложнее каталог кодов ошибок и совместимость API расширений. Произвольное выполнение команд из профиля не становится поведением импорта по умолчанию.
