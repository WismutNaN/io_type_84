# Aether-HE

Источник: [MrWhosNexus/Aether-HE](https://github.com/MrWhosNexus/Aether-HE), локальный commit `2179fd768fcdbb86f59c4c240b4d4cfcbc18936f`. Python + hidapi + web UI. В исследованном корне не найден LICENSE/COPYING; явное разрешение на перенос кода не установлено. Пока используем материалы для анализа, а реализацию пишем самостоятельно. Полный checkout остаётся в `archive_data/reference_projects/Aether-HE/`.

## Выбор нужного адаптера

| Файл | Модель/идентификация | Применимость |
|---|---|---|
| `protocol.py` | Aula Win60 HE, `2E3C:C365` | Другая ветка протокола |
| `protocol_sayo.py` | Sayo, `8089:0009` | Не основание транспорта IO |
| `protocol_sonix.py` | Mini60 Max, `0C45:80A1` | Экспериментальный формат RT с big-endian полями и иным payload; не наш codec |
| **`protocol_mini60.py`** | Mini60 Pro, USB `0C45:80A2` | Близкий HFD AA/55, FF68, 64-байтовые пакеты, RT little-endian |

В `data/board_registry.json` IO `80D6` не найден. Нельзя выбирать `protocol_sonix` по названию чипа или одному VID. Протокол Mini60 поддерживает ещё донгл, но это не проверка беспроводной IO и не входит в наш первый этап.

## Размеры и семантика

| Блок | Mini60 Pro в коде | IO White 1.17 |
|---|---:|---:|
| GET info | 56 байт | Проверено 48 |
| Общие настройки | 64 байта | Проверено 56 |
| GET keymap | 512 байт | Проверено 512 |
| SET keymap | 504 байта / 126 записей | Запись не проверена; прочитано 128 записей |
| RT | 1008 байт / 126 записей | Прочитано 1024 / 128 |
| Индивидуальный RGB | 504 байта / 126 записей | Прочитано 512 / 128 |
| DKS | 1024 байта / 64 записи | Прочитано 1024 / 64 |

RT `[axisType, flags, tripLE16, pressLE16, releaseLE16]` совпал во всех 128 IO-записях. Единица Mini60 — 0,01 мм; это подходит текущему `rtPrecision=0`, но не всем версиям IO. У parser есть особенность: он считает записи по длине физического кадра, игнорируя payload length. На нашем последнем пакете 16 байт получается пять лишних нулевых записей. В тесте явно отброшен padding: 133 сырых позиции → 128 действительных.

Не переносить default sizes или предположение, что нулевую/неизвестную запись можно заменить дефолтом. Сам факт round-trip не проверяет поведение RT, смысл флагов или аппаратную запись.

## Аналоговый поток и временный RGB

В первую очередь читать `docs/context/issue-6-mini60-pro-raw/HFD_SDK_DECODE.md`, затем соответствующие функции `protocol_mini60.py` и захваты в той же папке. Материал ссылается на HFD SDK с `hub.aulacn.com`; перечисление возможностей SDK шире проверенных автором функций конкретной платы.

**Analog.** В общем коде IO также есть `startSimulationTest` (`66`), `stopSimulationTest` (`67`) и parser уведомлений `55 FB`. Это отдельный путь относительно неоднозначного GET `68`. Поля совпадают с §12 HFD-документа Aether:

| Байты всего входного отчёта | Parser IO `cu` | Таблица Aether HFD SDK |
|---|---|---|
| 2 | keyValue | keyValue |
| 3 | calibrationStatus | calibrationStatus |
| 4–5 | maxValue LE16 | max ADC |
| 6–7 | minValue LE16, mask 0x7FFF | min ADC |
| 8–9 | currentValue LE16 | current ADC |
| 10–11 | keyStroke LE16 | stroke |
| 12–13 | maxStroke LE16 | max stroke |

Следовательно, parser для IO нужно проверять на собственном capture, минимум 14 байт. Текущая JS-проверка `length>=13` недостаточна для чтения последнего поля. Значения пока нельзя публиковать как измеренную силу или доказанный непрерывный поток всех 84 клавиш. Для отдельного эксперимента нужны ограниченная сессия, явный start/stop и восстановление режима; команды ещё не отправлялись.

**RGB.** IO USB-ветка использует `GET_LED_DATA` (`32`) с исходящим payload цветов и `CLEAR_LED_DATA` (`36`). Название GET здесь не означает чтение. Aether описывает этот путь как временный RGB; на IO его временность, частота и адреса не проверены. `SET_LED_DATA` (`42`) — другая команда для анимационных данных, не синоним `32`. Поток не строить через постоянные SET `24`, пока не установлены persistence и ограничения.

**Панель.** В SDK есть `1B/2B` light box, `1D/2D` side light и `2A` dot matrix. Для первых двух используются 24 байта: mode/R/G/B `[0..4)`, color mode `[8]`, brightness `[9]`, speed `[10]`; остальные байты сохранять. `2A` содержит два RGB и type/mode в 8 байтах. Ни один из этих блоков не следует автоматически объявлять нашей LED-панелью. Native GET `1B` на IO дал тайм-аут; [подробности](../LED_PANEL.md).

## Как оценивать свидетельства

В архиве есть старые spec/context-файлы, где поддержка Mini60 или донгла ещё отсутствует, и более поздняя реализация с захватами. Проверять current registry, конкретную функцию и packet capture вместе. Статус `SOURCE-ONLY` не равен проверке на клавиатуре, а захват Mini60 не равен захвату IO.

Самые полезные части сейчас: framing, RT, реконструкция макросов/advanced keys и метод сопоставления SDK с packet captures. Универсальная совместимость, firmware flasher для IO и гарантированная работа live analog из этого не следуют.
