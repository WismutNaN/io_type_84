# Протокол IO: рабочая спецификация

Статус: частично исследован на IO Type 84 Magnetic White `0C45:80D6`, версия `1.17`, frameVersion=0. Название адаптера в нашем проекте: `io_vision_v0`; это внутреннее имя, а не установленное название производителя протокола.

## Подключение

Выбрать HID-путь по VID/PID, usage page `FF68`, usage `0061` и родительскому USB-устройству. При нескольких кандидатах не выбирать первый. Сверить product string, характеристики дескриптора и GET_DEVICE_INFO. Пустой USB serial не позволяет построить постоянную идентичность только по серийному номеру.

MI_02: Output/Input по 64 байта, report ID=0. Через hidapi `write` передаётся нулевой ID и 64 байта payload. Чтение этого устройства возвращало 64 байта, начиная с `55`, без дополнительного нулевого ID. Для других report descriptors нормализация должна определяться адаптером, а не удалять первый байт безусловно.

MI_03: 4096-байтовый Output и 64-байтовый Feature. Только открытие и дескриптор проверены. Не использовать его как замену MI_02 или для RGB до отдельного исследования.

## Пакет MI_02

Индексы ниже относятся к 64 байтам содержимого, без байта ID hidapi.

| Смещение | Размер | Запрос | Ответ |
|---|---:|---|---|
| 0 | 1 | `AA` | `55` |
| 1 | 1 | Команда | Команда ответа |
| 2 | 1 | Размер порции; у иных команд возможен тип | Для проверенных GET — размер порции |
| 3 | 2 | Адрес, little-endian | Адрес ответа |
| 5 | 1 | Ноль для проверенных GET | Сохранить как raw |
| 6 | 1 | 1 для последней порции, иначе 0 | В проверенных ответах отражён |
| 7 | 1 | Ноль для проверенных GET | Сохранить как raw |
| 8 | до 56 | Данные, если они нужны команде | Данные ответа |

Блок разбивается на порции до 56 байт. Адрес следующей порции увеличивается на 56. Последняя порция задаёт фактический остаток. Для обычного GET запрос содержит нули в области данных. Исключение — статус осей, где сайт передаёт список идентификаторов.

Минимальный проверенный запрос информации: `AA 10 30 00 00 00 01 00`, затем 56 нулей. Запросить 48 байт информации; прочитать 64-байтовый ответ; взять payload `[8..56)`.

Ответы соединять после проверки команды, адреса, размера и общей длины. Неподходящие пакеты маршрутизировать отдельно как уведомления либо отвергать. Короткий пакет не дополнять нулями до «успеха». В исследованных GET нет проверки CRC; алгоритм CRC в общем bundle не означает наличие CRC у каждого пакета.

## Карта команд

Числа в таблице — hex. «Прочитано» означает успешный обмен и сохранение raw-данных; не полную интерпретацию всех полей.

| Чтение | Запись | Назначение | Известный объём | Проверка |
|---|---|---|---:|---|
| `10` | — | Информация | 48 | Прочитано |
| `11` | `21` | Общие режимы, частота, мёртвые зоны | 56 | Прочитано |
| `12` | `22` | Основные назначения | 128 × 4 | Прочитано |
| `16` | `26` | Fn-назначения | 128 × 4 | Прочитано |
| `13` | `23` | Эффект подсветки | 16 | Прочитано |
| `14` | `24` | Индивидуальные цвета | 128 × 4 | Прочитано |
| `15` | `25` | Макросы | Каталог 100 × 4 + тела | Прочитан каталог |
| `17` | `27` | Ход и Rapid Trigger | 128 × 8 | Прочитано |
| `18` | `28` | DKS | 64 × 16 | Прочитано |
| `1C` | — | Заводская Fn-матрица | 512 по сайту | Не проверено |
| `1F` | — | Заводская основная матрица | Не установлено | Только имя в bundle |
| `1B` | `2B` | Light box | 24 по SDK | GET: тайм-аут 1000 мс после успешного GET info; связь с панелью неизвестна |
| `1D` | `2D` | Side light | 24 по SDK | Не отправлялось |
| `68` | — | Состояние выбранных осей | 8 байт на позицию | Ответ неоднозначен |
| — | `32/36` | Временные LED-данные / очистка | Зависит от модели | Только код SDK; `GET_LED_DATA` (`32`) фактически отправляет данные |
| `33` | — | Цвета всех LED | 512 по сайту | Не проверено |
| — | `35` | Временные музыкальные/RGB-данные | Зависит от пути | Не проверено |
| — | `40/41/42` | Анимации/LED-данные | Зависит от модели | Только код сайта |

Изменяющие режим команды `64/65`, `66/67`, `69/6A` относятся к калибровке/симуляции. Команда `0F` — сброс; `80…86` — операции OTA в bundle. Они **не входят** в диагностический allowlist. Наличие кода обновления не является основанием добавлять прошивку в MVP.

Для simulation найден входящий `55 FB` с ADC/ходом; это уведомление, не GET. Native Rust и UI получили поток после `66`, stop `67` отправлен при завершении. Смещения совпадают с HFD-документом Aether; [сверка и минимальная длина](reference-projects/AETHER_HE.md#аналоговый-поток-и-временный-rgb). Пришли лишь два адреса с ходом до 0,18 мм, поэтому соответствие всем физическим клавишам и полный ход ещё не подтверждены.

## Декодирование основных блоков

### Информация

В 48-байтовом payload: VID в `[4..6)`, PID в `[6..8)`, sensor `[10..12)`, manufacturer `[12..14)`, product `[14..16)` — little-endian. Версия: младший байт `[8]` содержит десятичные цифры дробной части в двух полубайтах, `[9]` — целая часть. В снимке `17 01` означает `1.17`. Поля currentProfile `[19]`, rtPrecision `[29]`, frameVersion `[30]`, lightingVersion `[31]`. Не придумывать BoardID из другого SDK.

Уточнение по макросам: `[2..4)` = `00 92`, raw u16le = **37376**. AK820 parser называет его macroSpaceSize. В коде IO значение берётся из устройства только при `macroConfig.isGetMaxMacroSpaceSize`, иначе подставляется **512**. Именно 512 находится в пользовательском экспорте. Ни 512, ни 37376 пока не являются проверенной доступной ёмкостью макросов: нужны модельные ограничения, адреса/накладные расходы и контролируемая запись. Не расширять границы чтения/записи только по этому числу.

### Назначения и геометрия

Каждая запись: pageType, param1, param2, param3. Не интерпретировать её как один HID keycode: здесь кодируются также специальные действия и режимы. Сначала сохранить все 128 записей. UI использует отдельную карту 84 физических клавиш. Неизвестные pageType должны пережить чтение, экспорт и изменение соседней клавиши без потерь.

### Rapid Trigger

Запись 8 байт: axisType, flags, triggerKeyStroke:u16le, pressRT:u16le, releaseRT:u16le. По сайту делитель press/release равен 1000 при rtPrecision>0, иначе 100; делитель trigger равен 1000 при rtPrecision=2, иначе 100. В этом экземпляре rtPrecision=0. Пример A: `00 00 DF 00 00 00 00 00` → trigger 2,23 мм по алгоритму сайта.

Флаги bit0 и bit1 сайт называет isWholeFast и isRampageMode. Их поведение следует проверять физически. Поля домена хранить целыми микрометрами, конверсию и допустимый шаг определять capabilities; не округлять молча.

### Цвета, DKS, макросы

Индивидуальный цвет занимает 4 байта: адрес LED и RGB. Физическая клавиша, адрес назначения и адрес LED — разные типы, даже когда значения совпали.

Таблица DKS содержит 64 записи по 16 байт; часть полей кодирует четыре действия и состояния на этапах хода. Нулевая таблица в текущем снимке не доказывает исполнение DKS. Перед записью нужны семантические примеры из редактора и обратная проверка.

Каталог макросов содержит 100 смещений u32le. Проверять пределы адресов, длины, число действий и переполнение перед чтением тел. Значение 100 — формат каталога, а не обещание 100 длинных макросов: ёмкость памяти требует проверки.

## Требования к записи

Реализованы raw snapshot → diff → проверка identity/ревизии → backup с flush → SET полного изменённого блока → GET и побайтное сравнение. На White 1.17 проверены `22/26/23/24/25/27/28` с восстановлением. [Эксперимент](evidence/native-write-roundtrip.json). SET `21` есть в коде, но не отправлялся в аппаратном тесте.

Не считать ACK доказательством сохранения в энергонезависимой памяти. Не обещать атомарное изменение нескольких блоков. При разрыве связи отметить результат «неизвестен», перечитать после подключения и предложить восстановление. Повторять неизвестно завершившийся SET автоматически нельзя. Возможность записи одной позиции изучить до реализации: сайт часто отправляет блок целиком.

Проверенные GET допускают ограниченный повтор после тайм-аута, но в протоколе не найден номер транзакции. Поздний ответ с той же командой/адресом трудно отличить от нового: сеанс после тайм-аута должен переходить в восстановление и очищать/перепроверять обмен, а не продолжать очередь как ни в чём не бывало.

## Граница знания

Запись перечисленных блоков подтверждена через GET. Исполнение назначений/RT/advanced/макросов, устойчивость после отключения питания, аппаратные профили и полное физическое соответствие FB не верифицированы. Подавление событий ОС и потоковая RGB-анимация не реализованы. [Покрытие](EDITOR_IMPLEMENTATION.md).

## Уточнения codec из реализации

- Lighting SET `23`: byte 4 = FF, bytes 14/15 = AA/55 — write-only маркеры. GET возвращает сохранённые значения без этих маркеров. Передача маркеров и ожидаемый raw readback разделены; первый тест поймал ошибочное сравнение, исходное состояние восстановлено.
- RT: bit 0 byte 1 — `isWholeFast`, bit 1 — Rampage. Rapid Trigger определяется ненулевыми press/release, а не bit 0. При precision 0 три u16LE конвертируются в мкм умножением на 10. Тип оси и остальные флаги сохраняются.
- MOUSE: запись `[1, 1, buttonMask, 0]`, маски 1/2/4/8/16; колесо `[1, 3, 1 либо 255, 0]`. Это не порядковый номер кнопки в первом параметре.
- MACRO binding: `[6, id, mode, repeats]`. Сайт пишет repeats только при mode=1; новый редактор задаёт mode=1 и явное число повторов. Для mode 0/2 ожидается repeats=0. Catalog 100×u32LE, header `[actions×2:u16LE, 0, 0]`, действие `[delay:u16LE, keyCode:u8, (kind<<4)|downBit]`, kind1=keyboard/3=mouse, downBit=80. Запись ограничена 512 байтами, unknown header/flag bits блокируют перепаковку.
- CB `[7, modifierKeyCode1, modifierKeyCode2, regularKeyCode]`, modifier — HID 224…231 либо ноль. MT `[9, holdKey, tapKey, timeout/10]`; TGL `[10, keyCode, 0, 0]`.
- SOCD `[11, mode1…4, physicalKeyCode1, physicalKeyCode2]`, RS `[12, 0, physicalKeyCode1, physicalKeyCode2]`. Пара записана в двух физических слотах; это HID keyCode, не slot. Разрыв пары очищает оба назначения. Не более 40 advanced назначений; одна физическая клавиша не получает advanced в обоих слоях.
- DKS `[8, index, 0, 0]`. 16-байтовая запись: четыре порога в десятых мм; action keycodes в offsets 5/7/9/11; offsets 12…15 — четыре фазы, low nibble краткое действие, high nibble удержание. Остальные байты сохраняются.
- FUNC `[13, value>>16, value>>8, value]`. Редактор разрешает проверенный по сайту каталог подсветки/Win lock и действий панели. Reset/смена транспортного режима в каталог записи не включены. Найдены Fn+G=87, Fn+K=91, Fn+L=27; [панель](LED_PANEL.md).
- `GET 33`: native ответ побайтно равен 128 отправленным query-записям `[ledId,0,0,0]`. `current_colors` возвращает `ambiguousColors`; UI не показывает такой результат как измеренные цвета.
