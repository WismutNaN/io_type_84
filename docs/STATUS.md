## Новое: штатный ввод проверен глубже

[Разбор и воспроизведение](firmware/stock-input-v1.17.md): оригинальный ARM подтвердил
no-output `[5,0,0,0]`, media aliases в DKS/MT, маски модификаторов DKS, выбор MT
и перестановку Win/Alt режимом Mac. Исправлены типы макросов и проверка фаз DKS;
ложная кнопка отключения удалена. F13–F24 и шесть media actions доступны в редакторах.
Это не приёмка всей схемы helper.

На железе захват PgUp/PgDn через `[5,0,0,0]` в base/Fn **подтверждён**:
положительный Raw Input до/после, отсутствие исходного вывода одновременно с FB,
контроль наблюдателя пробелом. Пики до 3,98/3,96 мм, возвраты к нулю в base-only
прогоне. [Свидетельство](evidence/stock-capture-acceptance-v1.17.json). Назначения
восстановлены; владелец подтвердил. G1 принят для двух клавиш и этой firmware.
Следующий шаг — приложение light/deep и его фактический Windows-выход.
OS-mode (Fn+M) вне девяти блоков snapshot. Capture-extension для этого сценария не нужен.

## Приоритет продукта

После `objects.md` владелец разрешил сложные жесты/слои/обработку в helper при
надёжном поведении. Подготовлены 25 групп объектов и покрытие 33 разделов.
[ADR-0009](adr/0009-behavior-model-and-execution.md) — **предложение**, stock + B
для всего графа пока не доказан. Перед расширением модели в production —
G1/G2: владение исходным вводом и выходами; G3/G4/G5 отдельно для analog/света.
[Совместимость](objects/COMPATIBILITY.md), [M0–M4](../modules/execution-plan.md).

1. **A — штатная настройка:** максимально раскрыть доступные параметры и макросы,
   принять физическое исполнение/сохранение. Перепрошивка и фон не требуются.
2. **B — помощник:** довести существующий Windows worker до работы без редактора,
   добавить цифровой источник, выбор программы/аргументов и opt-in автозапуск.
3. **C — расширение устройства:** отдельное исследование там, где stock API
   недостаточен. Начальный кандидат — временный API полосы. Не блокирует A/B.

Это принятый план, не три готовых режима EXE. [ADR-0007](adr/0007-integration-levels.md).
Сетевые уведомления и действия ОС требуют помощника даже с новой firmware.

Владелец сообщил об отказе производителя предоставить материалы. Следующий выпуск
планируется на штатной firmware: **самостоятельный фон и цифровые действия**, рядом
с физической приёмкой A и кандидата DKS/MT/Fn → отдельный код → действие B.
Мост ещё не проверен; он может снять зависимость части условий глубины от analog.
[ADR-0008](adr/0008-stock-first-delivery.md). README обозначает независимый статус
репозитория и содержит ссылки IO; не является журналом обращения к производителю.

## Что уже есть

**Открытый дефект поведения:** владелец подтвердил одновременные PgUp и громкость
при глубоком нажатии. Код реализует добавочные независимые жесты; исключающего
выбора пока нет. Рекомендуемый ближайший проверяемый сценарий —
[PgUp/PgDn с одним результатом за цикл](../modules/automation.md#exclusive-depth),
включая контроль исходного ввода. Разработка фона продолжается, но расширение
каталога не считается решением этого дефекта. Это пользовательское наблюдение,
не новая измеренная гарантия analog; устройство в этой сессии не проверялось.

ProcessAction **пока нет**. Варианты Linux/macOS сохраняются, но adapters не реализованы.
Скрипты, LLM/почта/Telegram, контекст приложения и программные слои запланированы.

## Аппаратные границы

- Native snapshot и 20 с FB: 19 833 пакета, только два адреса, максимум 0,18 мм;
  конфигурация не изменилась. [Свидетельство](evidence/native-rust-initial.json).
- Яркость и base/Fn/RT/RGB/несвязанные macro/DKS прошли SET → GET → restore;
  итоговая ревизия совпала. Исполнение назначений, сохранение после снятия питания
  и SET 21 ещё не приняты. [Свидетельство](evidence/native-write-roundtrip.json).
- Макрос записывается в память устройства. **512 байт — ограничение текущего writer**,
  полная полезная ёмкость не установлена; каталог 400 байт не означает 100 длинных
  макросов. Не увеличивать лимит без исследования адресов; unknown данные сохранять.
- GET 33 даёт эхо, текущий RGB неизвестен. Stock 32 пишет RGB клавиш в RAM и имеет
  таймер; реальное время/возврат не проверены. Пустой 32 продлевает режим. Streaming
  в desktop не включён. [Разбор света](firmware-lighting-v1.17.md).
- Полоса отдельная: под Del/PgDn; десять логических позиций по HEX, физическая карта
  не принята. FUNC 27/87/91 найдены; прямого stock setter нет. [LED_PANEL](LED_PANEL.md).

## Что получено по firmware

OpenAula и Sonix DFP — выбранная основа. Восстановлены карта памяти, калибровка,
ISP payload, атлас 436 кандидатов функций, начальная RAM и USB callbacks.
Полоса проверена в оригинальном ARM encoder в эмуляторе: подмена только десяти
позиций, следующий stock-кадр восстановлен. [База](firmware/README.md),
[контракт](firmware/panel-host-api.md), [Rust-прототип](../experiments/panel-api/README.md).

Прототип CAPS/FRAME/RELEASE, TTL и session: 8 Rust-тестов, Clippy, ARM no_std
библиотека; 19 Python-тестов без пропусков. Это не функция устройства. Две call sites
найдены; размещение/ABI/USB lifecycle ещё не привязаны. Нет полного backup устройства,
индивидуальной калибровки, Code Option/SM, подтверждённого recovery/downgrade.
Клавиатуру не прошивать; сторонний OpenAula dry run также не запускать.

## MCU и новые сценарии — оценка 2026-09-14

Получен полный официальный manual Sonix v1.7, 569 с. Семейство SN34F280 имеет
M4/FPU до 192 МГц, 160 КиБ RAM; точный MCU/PCB и частоты IO ещё не подтверждены.
По manual CS1→CS0 стирает User, CS3→CS0 также Boot. BOOT зависит от BOOTPINEN;
автоматический unlock ради backup недопустим. Статус защиты устройства неизвестен.

[Возможности и ограничения](firmware/chip-feasibility.md),
[flash/security и расхождения](firmware/sonix-manual-safety.md),
[полная матрица cases](FEATURE_MATRIX.md),
[история запроса IO/OEM](firmware/manufacturer-request.md).
Аппаратный Protection требует изменения тракта до HID; для замены составных
нажатий на ПК возможен отдельный перехват ОС или выделенное stock-назначение.
Слои/правила выглядят посильными для MCU, но бюджеты пока расчётные, analog не принят.
Сетевые условия остаются в помощнике. C продолжается для доказанного пробела A/B;
идентификация/backup/recovery перед аппаратным переносом обязательны, комплект IO
больше не ожидается. Основное приложение этой систематизацией не менялось.
