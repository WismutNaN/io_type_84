# План реализации

Стек: Rust + Tauri 2 + TypeScript + Vue 3. Первая платформа: **Windows + USB, подтверждено пользователем**. Проект открытый; платформенные адаптеры должны позволять добавление других ОС. Фазы ниже — проект последовательности, не выполненные работы. Каждая оставляет запускаемую систему. Размер фазы ориентировочно 1–5 рабочих дней одного разработчика; при превышении объёма фазу разделить до начала реализации, не скрывать незавершённость.

Исследование до реализации завершено частично: native open и GET подтверждены, SET/live analog/RGB streaming не проверены. Свидетельства — [DEVICE_RESEARCH](DEVICE_RESEARCH.md). Для каждой фазы читать указанные модули и её контекст.

<a id="phase-1"></a>
## Фаза 1 — компилируемый скелет

**Цель:** запускаемый Tauri/Vue и независимый Rust workspace. **Результат:** окно с состоянием «Устройство не подключено», CLI help. **Трудоёмкость:** S, 1–2 дня. **Статус:** [ ] Не начата.

**Контекст для агента:** в репозитории только документация и игнорируемые референсы. Не копировать приложение AureTrix целиком. Структура и зависимости описаны в архитектуре; бизнес-логика этой фазы отсутствует.

### Задачи
- [ ] Создать workspace, core/platform/cli и Tauri composition root → [структура](ARCHITECTURE.md#structure), [адаптеры](../modules/adapters.md).
- [ ] Создать Vue shell, навигацию и отображение статуса → [UI](UI.md), [границы UI](ARCHITECTURE.md#components).
- [ ] Закрепить версии зависимостей, lockfiles, Windows prerequisites и команды разработки → [ADR-0001](adr/0001-stack.md), [адаптеры](../modules/adapters.md).

### Проверка

- [ ] Core компилируется без зависимостей от Windows/Tauri; CLI не открывает HID.

**Контекст для агента:** скелет работает. MI_02 `FF68:0061` принимает 64-байтовые пакеты; raw-снимки содержат 80 проверенных обменов. Записи ещё нет.

### Задачи
- [ ] Реализовать enumeration/open/close и идентификацию → [device](../modules/device.md), [PROTOCOL](PROTOCOL.md).
- [ ] Реализовать allowlist GET, decode снимка и корректную обработку тайм-аутов → [adapters](../modules/adapters.md).
- [ ] Загрузить 84-клавишную карту с разреженными адресами и показать прочитанное → [configuration](../modules/configuration.md), [application](../modules/application.md).

### Проверка
- [ ] Codec принимает реальные fixtures и отвергает неверную длину/адрес/команду; число физических клавиш 84, слотов 128.
- [ ] На устройстве получены VID/PID и 1.17; keymap/Fn/RT совпадают с непосредственным чтением.
- [ ] Unplug, занятость и два кандидата дают явные состояния. Ни один SET не достижим через диагностический CLI.

### Проверка

- [ ] Физическая клавиша выполняет назначение; исходное поведение восстановлено.
- [ ] Переподключение проверяет сохранение отдельно. Обрыв после отправки SET даёт Uncertain, не ложный успех.
