# Расширение firmware для модели объектов

Дата: 2026-09-14. **Требования к возможному расширению, не существующий API и не
разрешение на прошивку.** Владелец допускает сложные recognizers/слои в helper.
Значит, первый кандидат C — небольшой input/output bridge, а не перенос всех
объектов, plugins и Flow на MCU. [Модель](../OBJECT_MODEL.md),
[gates совместимости](COMPATIBILITY.md), [планировщик](../../modules/execution-plan.md).

## Почему сохранится архитектура

Profile/Control/Recognizer/Condition/Flow описывают поведение. Transport adapter
сообщает доступные сигналы, способ владения вводом, выходы и допустимые budgets.
Расширение заменяет недостающий Input/Output contract и допускает новые execution
plans. Поэтому в Rule не появляется `if firmware_custom` для каждого действия.

Это граница проектирования, не гарантия отсутствия любых будущих миграций. Новое
поведение может потребовать новый тип/версию IR. Совместимость обеспечивается
версионированием, проверочными traces и отказом от молчаливой потери семантики.

## Два разных объёма C

| Вариант | Что делает firmware | Что остаётся на ПК |
|---|---|---|
| C-bridge, предпочтительный при провале stock gates | Передаёт нужные input-события, уступает выбранный обычный ввод, принимает контролируемые выходы/свет с TTL | Recognizers, сложные слои/условия, Flow, actions каталога, providers |
| C-autonomous, только для отдельного требования | Ограниченный набор processors/recognizers/условий, таблицы слоёв и локальные выходы | OS/network/plugin действия и authoring; полный язык host туда не переносится |

Поддержка полосы не доказывает пригодность input bridge. Вставка в RGB encoder
и вмешательство в формирование обычного HID имеют разные call sites, ABI и риски.
Первоначальный [IOLQ-прототип](../firmware/panel-host-api.md) покрывает только полосу;
он не реализует перечисленные ниже команды.

## Минимальные контракты для bridge

Имена — логические операции, **числовые opcodes, packet layout и адреса не назначены**.
Не отправлять их устройству по сходству с командами другого SDK.

| Группа | Требуемое поведение | Что нужно доказать на IO |
|---|---|---|
| Capability negotiation | Уникальный ответ, версия, limits, supported signals/targets, модель владения | Stock echo не проходит handshake; ревизия firmware/платы совместима |
| Input subscription | PhysicalControlId, digital/analog тип, порядок/sequence, исходное состояние, качество времени | Полная карта и источник до/после RT; выборки и события не смешаны |
| Input ownership | Volatile маска controls, которые не выдают обычный HID, пока их решает host | Эффект до обычного отчёта, Fn/consumer/модификаторы, взаимодействие с stock RT/DKS |
| Output ownership | Session-scoped leases/key state; один compositor для stock и host вкладов IO | Не отпускать чужой вклад; обработать reordering, дубликат, потерю и переполнение |
| Lighting surfaces | Независимые key/panel frames, геометрия, frame replace, TTL/release | Карты/частоты, нагрузка на сканирование и возврат stock renderer |
| Session / failover | Generation, timeout, disconnect/suspend, release, безопасное восстановление | Не воспроизводить старые action IDs, не порождать новый tap при смене владельца |
| Diagnostic status | Активный владелец/версия, counters потерь, accepted vs applied | Ответ принятия не выдавать за физическое действие; bounded trace |

Input lease должен истекать на устройстве, а не зависеть от успешного последнего
пакета helper. При истечении снять только host output contributions. Возврат
stock-ввода уже удерживаемой клавиши требует явно выбранной политики: например,
дождаться её отпускания перед новым stock циклом. Нельзя внезапно выдать PgUp
из ранее отменённой глубокой ветки. Аналогично обрабатываются новые session и reset.

Дедупликация/sequence нужна для RAM-выходов, но не создаёт exactly-once семантику
почты/HTTP. Эти эффекты имеют собственные правила повторов на ПК. Источники других
физических клавиатур остаются вне compositor IO; общесистемную гарантию проверяет
OS adapter, а не один firmware lease.

## Если потребуется автономный runtime

Передача новых команд может добавить параметры существующих функций, но сама по
себе не создаёт произвольные Recognizer/Flow. Для автономных версий нужны код
автоматов, их конфигурационный формат, states/timers, storage и ограничения.

Предпочтителен ограниченный типизированный IR: известные operators, версии,
фиксированные единицы, явные пределы controls/nodes/timers/leases/call depth,
worst-case budget на tick. Произвольные циклы, shell, HTTP и plugin-код не являются
допустимыми устройственными узлами. Не объявлять MCU способным исполнять любой
host-граф по одному размеру RAM.

Конфигурация сначала валидируется и активируется в RAM. Persist — отдельная операция
с версией/целостностью/проверкой восстановления. Требования stage/validate/activate/
readback/explicit-save — проект нового формата; у stock нет общей транзакции этих
объектов. Начальная RAM/нули HEX не являются доказательством свободного места.

## Реальность переноса и условия продолжения

OpenAula/официальные DFP/manual — основа, штатные HE/RT/USB routines по возможности
сохраняются. Для bridge исследовать точки выдачи HID, доступные сигналы, сохранение
контекста регистров/FPU, стеки/DMA, scheduler, reset/suspend и конфликт с stock macro.
Это дополнительная работа сверх найденного RGB encoder. Прошивка производителя
не предоставлена; её отсутствие не заменяется предположениями о простом патче.

До записи обязательны точная плата/MCU, сохранность индивидуальной калибровки,
backup нужных областей и проверенный recovery на подходящем стенде. Code Security
не переключать ради чтения: определённые переходы стирают User/Boot.
[Основания](../firmware/sonix-manual-safety.md), [план recovery](../firmware/update-recovery.md).

Порядок выбора: G1/G2 на stock → приёмка подходящего готового OS backend либо
фиксация неприемлемых ограничений → offline proof конкретного bridge → recovery →
отдельная разрешённая аппаратная сессия. G3/G4/G5 рассматриваются независимо.
Пока доказательства не получены, C остаётся предлагаемым исполнителем; в UI нельзя
показывать полную поддержку модели ни для stock, ни для будущей firmware.
