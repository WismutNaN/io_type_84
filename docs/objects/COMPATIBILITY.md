## Уровни доказательства

**A** — выражается известной штатной конфигурацией; **B** — реализуется помощником;
**C** — требует добавляемого firmware-контракта для выбранного способа исполнения.
«B» не означает, что нужный host-код уже написан или прошёл аппаратную приёмку.
«Не представимо в известном A» не является доказательством отсутствия любого
скрытого алгоритма в ROM; это отсутствие пригодного подтверждённого контракта.

Отдельно учитываются: представимость → существующий encoder → SET/readback →
физическое поведение → сохранение после питания → работа при отказе.
Не выводить последние стадии из первых. В этом обзоре HID не использовался.

## Что действительно можно записать штатно

Числа команд ниже hex; номер binding page указан десятичным. Основание:
[PROTOCOL](../PROTOCOL.md), `keyboard.rs` и `changes.rs`.

| Проекция намерения | Штатная запись | Граница |
|---|---|---|
| Обычное назначение / Main-Fn | `22/26`, 128 × 4; page 0/1/2/3/7/13 | Default/mouse/keyboard/media/chord/FUNC. Page 0 и `[2,0,0,0]` не выключают клавишу; кандидат no-output — `[5,0,0,0]`, пока только стенд |
| Порог и RT | `27`, 128 × 8 | Параметры stock алгоритма; не загружаемый Processor |
| Частота/deadzone | `21`, 56 | Encoder есть, аппаратный SET 21 не принят |
| DKS | `28`, 64 × 16 + binding `[8,index,0,0]` | 4 порога/4 action codes с масками modifiers/4 фазовых поля; коды включают фиксированные media aliases, не произвольный Flow |
| MT | Binding `[9,holdKey,tapKey,timeout/10]` | 2 keyboard codes, текущий validator допускает timeout 10…1000 мс с шагом 10. Interrupt/DecisionPolicy не кодируется |
| TGL | `[10,keyCode,0,0]` | Встроенный toggle одной клавиши, не общий StateStore |
| SOCD / RS | `[11,mode,key1,key2]` / `[12,0,key1,key2]` | Два согласованных назначения, фиксированные политики. Произвольные tie/priority-группы не кодируются |
| Macro | `25`, каталог 100 × u32 + линейные шаги; binding `[6,id,mode,repeats]` | Нет известных If/Wait-event/CallFlow/Parallel. Текущий writer всего 512 байт, из них 400 каталог |
| Свет клавиш | `23/24`: эффект и карта RGB | Параметры/статические цвета; не ActionFlow и не кадр фактически измеренного свечения |
| Режимы полосы | Назначение известных FUNC 27/87/91 | Код внутреннего действия; не прямой setter произвольного кадра |

84 клавиши не равны 128 слотам или 64 записям DKS. Текущий encoder ограничивает
advanced 40 назначениями и запрещает advanced одной физической клавиши сразу в
Main и Fn. Точные ограничения имеют происхождение codec/site, не произвольную
«ёмкость MCU». У macro остаётся всего 112 байт под заголовки/шаги в текущем writer;
это не установленный предел flash IO. Неизвестные поля/записи сохраняются.

SET/readback/restore выполнены для Main/Fn/RT/RGB/яркости/несвязанных macro/DKS;
см. [свидетельство](../evidence/native-write-roundtrip.json). Физическое исполнение
всех шаблонов и power-cycle ещё не приняты. Жалоба владельца о двойном PgUp
подтверждает проблему текущего additive-пути, а не пригодность exclusive-моста.

### Группы операций, которые нельзя потерять при реализации

- Recognizers: Edge, ThresholdCrossing, Range, Tap, Hold, TapOrHold, MultiTap,
  Chord, Sequence, AnalogChange, Compare, Velocity, Direction, Timer, AppEvent,
  Notification, PluginEvent. Композитные взаимодействия используют общие lifecycle
  и arbitration, но не обязаны быть одним универсальным алгоритмом.
- Actions: keyboard, mouse, InvokeControl, state, layers, profiles, application,
  window, system, script, network, plugin, lighting, notification. CallFlow находится
  среди управляющих узлов Flow. В каталоге это остаётся обычным выбираемым действием.
- Flow: Sequence, Parallel, If/Else, Choose, Delay, WaitCondition, WaitInteraction,
  Repeat, While, CallFlow, CancelFlow, Return. Размер, глубина, число запусков и
  бесконечные ожидания имеют явные ограничения/отмену. Stock не получает эти узлы
  только потому, что host может сохранить их в JSON.
- Lifetime: instant, while-active, source-release, timed, until-condition, toggle,
  manual, detached. Для конкретного типа операции перечисление сужается семантически,
  а не согласно удобству UI. Delete/HTTP не приобретают обратимость от lease.

## Проверки допуска stock + helper

| Gate | Что доказать | Что известно сейчас / последствие отказа |
|---|---|---|
| G1 — исходный ввод | Подходящие down/up без утечки обычного PgUp, нужная клавиатура, provenance, порядок, повтор и stop | Observer не подавляет. Stock-маркер — кандидат; можно исследовать готовый capture backend. При отказе — C input bridge либо явно ограниченный scope |
| G2 — выходное владение | Физический Shift + два правила, release одного, конец macro, другая клавиатура, crash/sleep | Сейчас короткий SendInput с проверкой конфликтов, не общий lease backend. При отказе нужен другой output adapter/C для контролируемого IO-выхода |
| G3 — analog | Нужные 84 control/address, полный ход/пики/release, одновременность, качество времени, потери | Прежний тест 2 адреса до 0,18 мм. Без G3 цифровые автоматы возможны; velocity/траектории не допускаются |
| G4 — RGB клавиш | Команда 32: цвет/адреса/частота/нагрузка, время возврата, stop/disconnect | Код RAM-write найден, аппаратная приёмка отсутствует. Не заменить потоком сохраняющих SET |
| G5 — полоса | Независимый управляемый вывод, lease/release, физическая карта | Stock 32 её не адресует; прямого setter нет. Сейчас нужен C либо отказ от произвольной полосы |
| G6 — config storage | Stock шаблоны исполняются как описано, readback/power-cycle/restore | Запись ряда блоков подтверждена; поведение и сохранение после питания отдельно не приняты |

G1/G2 — критерии для обещания полной обработки ввода в helper. Это существенная
граница, не косметическая недостающая функция. G3/G4/G5 независимы: цифровые правила
не должны ждать света, но аналоговый пресет нельзя считать работающим без G3.

## Готовые решения перед новым системным драйвером

Kanata — референс для цифровых автоматов и возможного input backend. В текущем
проекте есть Windows-варианты LLHOOK/SendInput и Interception, а пример конфигурации
позволяет выбирать hardware IDs для Interception. Это не аналоговый IO adapter.
Release notes также описывают известную проблему Interception с отключением устройств
до перезагрузки. Поэтому backend пока **не выбран и не установлен**; нужно закрепить
версию, проверить лицензию и пройти G1/G2 на целевой Windows.
[Kanata releases](https://github.com/jtroo/kanata/releases),
[пример конфигурации](https://github.com/jtroo/kanata/blob/main/cfg_samples/kanata.kbd).

Не переносить ограничения одного backend в доменные сущности. В то же время
нельзя назвать ненадёжный backend корректной реализацией только из-за подходящего
trait. Ни keyboard hook, ни stock-маркеры не объявляются универсальной гарантией
для всех программ, повышенных окон, игр и других клавиатур без матрицы приёмки.

## Решение о продолжении

При разрешённом helper богатая модель сохраняется. **Полное соответствие stock + B
сегодня не доказано**, и потери не ограничены одним Protection. Сначала ограниченная
проверка G1/G2 на PgUp/PgDn и leases; G3/G4 — отдельные эксперименты. После этого
можно принять конкретный deployment target без специальных обходов в каждом Rule.

Если G1/G2 требуют неприемлемого системного фильтра или не дают нужного поведения,
следующий шаг — узкий [firmware input/output API](FIRMWARE_CONTRACT.md). Это меняет
adapter и допустимые планы, а не смысл Control/Recognizer/Flow. Готовность такого
расширения требует отдельного доказательства ABI/ресурсов/recovery; её нельзя вывести
из наличия официального HEX. Полное автономное исполнение всех ОС-интеграций в MCU
не предлагается даже для C.
