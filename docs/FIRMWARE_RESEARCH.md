# Исследование прошивки White 1.17

Дата: 2026-09-13. Статический анализ файла; приложение не обновляет прошивку. Для продолжения достаточно этого файла, [протокола](PROTOCOL.md) и отчётов ниже.

## Источник и воспроизводимость

На [странице настроек производителя](https://web.io.vision/settings) предусмотрено обновление. [Каталог update.json](https://web.io.vision/update.json) содержит запись IO Type 84 Magnetic White, productId 32982, версия 1.17, `isHex: true`. Точное имя позволило скачать [IO_Type_84_Magnetic_White_V1.17.hex](https://web.io.vision/IO_Type_84_Magnetic_White_V1.17.hex) без перебора запросов.

Файл имеет размер **255 277 байт**, SHA-256 `8f5ef507771c6795258eb7521cfc1b46269a5b301548767ae87a3f1a83a50d45`. Версия совпадает с ответом подключённой клавиатуры, но это не доказывает побайтовую идентичность установленной прошивки.

Полный HEX и каталог остаются в игнорируемом `archive_data/firmware/2026-09-13/`. В Git находятся [источник и хеши](evidence/firmware-source.json), [структурный отчёт](evidence/firmware-white-v1.17-analysis.json) и собственный [анализатор](../tools/inspect_firmware.py). Код и бинарник производителя в продукт не включены.

Из корня репозитория, PowerShell и Python 3.10+:

```powershell
New-Item -ItemType Directory -Force archive_data/firmware/2026-09-13
Invoke-WebRequest 'https://web.io.vision/IO_Type_84_Magnetic_White_V1.17.hex' -OutFile archive_data/firmware/2026-09-13/IO_Type_84_Magnetic_White_V1.17.hex
python tools/inspect_firmware.py archive_data/firmware/2026-09-13/IO_Type_84_Magnetic_White_V1.17.hex
python -m unittest discover -s tools -p 'test_*.py'
```

## Измеренные результаты

| Параметр | Результат |
|---|---|
| Формат | Intel HEX, контрольные суммы всех записей корректны |
| Записи | 5677: 5672 data, 3 extended linear address, 1 start linear address, 1 EOF |
| Реальные данные | 90 728 байт |
| Сегмент 1 | `[0x00000000, 0x00016264)`, 90 724 байта |
| Сегмент 2 | `[0x0007DFFC, 0x0007E000)`, 4 байта |
| Start linear address | `0x000001C1` |
| Первое слово LE | `0x20007E48`, похоже на начальный stack pointer |
| Второе слово LE | `0x00000205`, похоже на Thumb reset vector с адресом кода `0x204` |

Адресный размах 516 096 байт не означает такой размер установленной flash. Назначение последних четырёх байтов неизвестно; не объявлять их CRC или подписью. Start linear address из HEX и предполагаемый reset vector — разные поля, их совпадение не предполагается.

В данных найдены USB-диагностические строки `[USBD]` около `0x10184`, `0x101D8`, `0x10228` и строка модели ` IO Type 84 Magnetic White` около `0x10B93`. Первые слова совместимы с таблицей векторов ARM Cortex-M. Пробная дизассемблировка Thumb по адресу `0x204` дала последовательность загрузок/записей и переход `bx r0` по `0x218`; это поддерживает гипотезу об архитектуре, но не определяет точную модель MCU. Анализатор сохраняет только структурные признаки; дизассемблер не является зависимостью проекта.

## Следующее исследование

1. Проверить таблицу векторов, карту памяти и происхождение USB-строк; установить MCU по нескольким независимым признакам.
2. Найти обработчик AA/55 и сопоставить его с уже прочитанными GET и кодом сайта.
3. Исследовать кандидаты команд панели из [LED_PANEL](LED_PANEL.md), сначала статически.
4. Подтверждать аппаратное поведение отдельно: наличие функции в бинарнике не доказывает её доступность этой модели или режима.

Не выполнялись прошивка устройства, запуск бинарника, извлечение flash или пробные SET. Корректная сумма Intel HEX проверяет целостность записи, а не цифровую подпись производителя.
