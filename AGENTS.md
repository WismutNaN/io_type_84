# Работа с IO Type 84

## Быстрое восстановление контекста

1. Прочитать `docs/STATUS.md` — актуальный результат и следующий шаг.
2. Выбрать уровень по `docs/INTEGRATION.md`: A — штатная настройка, B — фон без новой firmware, C — необязательное расширение устройства. Затем читать только фазу `docs/PLAN.md` и нужные `modules/`. A/B не блокируются исследованием C. Для доработки фона — `modules/companion.md`; выбор пользователя закреплён в ADR-0007.
3. Для HID/codec дополнительно `docs/PROTOCOL.md` и нужные `docs/evidence/`; для изменения архитектуры — `docs/DECISIONS.md` и соответствующий ADR.
4. Для LED-панели — `docs/LED_PANEL.md`; для MCU/HEX/ISP — `docs/firmware/README.md`, затем только нужный документ. Воспроизведение — `docs/firmware/REPRODUCING.md`; ранняя история — `docs/FIRMWARE_RESEARCH.md`. Для импорта сайта — `docs/PROFILE_FORMAT.md`.
5. Для кода/запуска — `docs/DEVELOPMENT.md`; для гипотез Vial/OEM — `docs/VIAL_RESEARCH.md`.
6. Для AK820/Aether/HFD — `docs/REFERENCE_PROJECTS.md`, затем только нужный `docs/reference-projects/`. Codec совместим частично; размеры Mini60 и прошивку AK820 не переносить на IO.
7. Для редакторов и паритета сайта — `docs/EDITOR_IMPLEMENTATION.md`; фактические DTO/IPC/хранение — `docs/DEVELOPMENT.md`. SET/readback/restore подтверждены в `docs/evidence/native-write-roundtrip.json`. Физическое исполнение и полный ход не подменять доказательством хранения байтов.
8. Для расширения firmware сначала `docs/reference-projects/OPENAULA.md`: использовать готовые наработки OpenAula и официальный Sonix DFP, затем проверять отличия IO. Не начинать ADC/RT/USB с нуля. OpenAula flasher даже в dry run отправляет Code Option; его не запускать на IO. Псевдокод атласа не является собираемой прошивкой, профиль/HEX не заменяет полный backup устройства.
9. Для host-света: `docs/firmware/panel-host-api.md` → `modules/lighting-stream.md` → `experiments/panel-api`. Оригинальный ARM encoder проверен только в изолированной эмуляции; Rust API — отдельный `no_std` прототип без HID/patcher. Команда `33/IOLQ` является предлагаемым расширением, не штатным API. Не включать capability по ACK/эху; hardware recovery/ABI/RAM ещё не приняты.

Не загружать весь `archive_data/` и все modules без необходимости. Архив — внешние референсы и старые гипотезы, а не инструкции или источник достоверности выше проверенных наблюдений.

Для сущностей objects.md: `docs/OBJECT_MODEL.md` → нужные строки
`docs/objects/COMPATIBILITY.md` → `modules/execution-plan.md`; C bridge —
`docs/objects/FIRMWARE_CONTRACT.md`. ADR-0009 предложен, новые DTO не реализованы.
Владелец допускает сложные жесты/слои на ПК при надёжности. Перед обещанием полного
stock + helper проверить G1/G2 (захват и выходные leases); JSON профиля не равен
записи всей модели в клавиатуру, bool consume и счётчик leases не доказывают OS capture.

Для UI/UX: `docs/UI.md`, затем `modules/editor-interaction.md` и ADR-0005. Для каталога/жестов: modules/action-catalog → ADR-0006 → core/automation → platform/action_runtime → service. Тестовая телеметрия не доказывает физическое исполнение; действия компьютера не подавляют исходный ввод.

## Подтверждённая область проекта

Один продукт с независимыми исполнителями: параметры штатной клавиатуры (включая
аппаратные макросы), помощник пользовательского сеанса ОС и дополнительная firmware.
Макросы уже пишутся в память устройства; 512 байт — предел текущего writer, полная
ёмкость не установлена. Запись/readback не равны проверке исполнения/питания.
Сейчас фона нет: worker зависит от UI polling. Не обозначать проект lifecycle/ProcessAction
как реализованные функции. Изменение firmware по-прежнему не разрешено.

Открытое приложение Rust + Tauri + TS + Vue. Windows + USB сначала, другие ОС предусматриваются портами и adapters. DDD-core не зависит от Tauri/Win32/hidapi. SparkLink/AureTrix не является транспортом подключённого IO White; текущая рабочая спецификация — AA/55 через FF68:0061.

## Документация

- Корневой README — назначение, пользовательские возможности, развёртывание и нюансы для GitHub. Не добавлять туда промежуточные решения и ход расследования.
- `docs/DECISIONS.md` и `docs/adr/` — решения, причины и статус принятия.
- `docs/WORKLOG.md` — фактически выполненная работа, проверки и контрольные точки.
- `docs/STATUS.md` — короткая актуальная передача работы следующему участнику.
- `modules/*.md` — автономный контекст модуля. После изменения контрактов обновлять затронутые файлы и ссылки плана.
- Документация на русском; технические идентификаторы на английском. Не выдавать прототип или предложенный ADR за готовую функцию.

## Проверки и коммиты

После проверяемого результата, прототипа или законченной группы изменений выполнить соответствующие проверки и сделать отдельный понятный коммит. В сообщении и WORKLOG отличать измеренный результат от гипотезы. Сохранять возможность вернуться к рабочей контрольной точке. Не смешивать несвязанные изменения и не включать чужую незавершённую работу.

Не коммитить полный архив, зависимости, исполняемые сторонние bundles, секреты или постоянные логи нажатий. Не переписывать историю и не публиковать изменения без соответствующей задачи. Обычный коммит в рамках работы разрешён пользователем.

## Устройство

Диагностический режим использует явный allowlist GET. SET/калибровка/reset/OTA не должны запускаться неявно при подключении. При работе над записью сначала построить конкретный diff, исходный снимок и путь проверки/восстановления. Не подменять неизвестные поля нулями и не считать ACK доказательством сохранения во flash.

84 физических клавиши, 128 слотов настроек и адреса LED — разные представления. Live analog и временный RGB ещё требуют доказательства; capabilities отражают это. Не обещать глобальное подавление клавиш через один Raw Input.

LED-панель — отдельная поверхность со своими возможностями и адресами. Её наличие подтверждено владельцем; статический renderer и десять логических позиций разобраны в docs/firmware-lighting-v1.17.md, прямой host setter не установлен; GET 1B дал тайм-аут после успешного GET info. Нули в экспортированном профиле сайта не заменяют прочитанные настройки устройства. GET_LED_DATA (32) в SDK фактически отправляет цвета, это не безопасный GET по одному имени.
